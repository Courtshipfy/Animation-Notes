# 查询数据与资源选择：Pose History、Trajectory、Chooser、Proxy Table

> 现代姿势选择需要知道：刚才的身体状态、接下来的移动意图、现在允许的资源，以及最终采用哪个变体。

## Pose History：保存跨帧的姿势证据

Pose History 是为 Pose Search / Motion Matching 保存一段历史骨骼姿势的 AnimGraph 节点。它不同于 Cached Pose：后者复用当前帧计算，前者提供跨帧运动历史。

它的原理是连续采样 Schema 关心的骨骼位置、旋转和速度。查询时，将当前历史与数据库候选动画在相同时间段的特征比较，所以系统不仅知道“这一帧腿在哪”，还知道“它刚才怎样运动”。采样骨骼和时间窗口越多，区分能力越强，成本也越高。

典型应用是起步接循环、左脚支撑切到右脚支撑、转身接跑步时，避免只因当前帧相似就跳到运动趋势相反的候选。它必须持续更新；只在进入状态时记录一次，查询到的会是过期姿势。

## Trajectory：把移动意图变成可比较的未来

Trajectory 是角色过去与预测未来的位置、朝向、速度采样序列，是 Pose Search Trajectory Channel 的输入数据，不是最终输出 Pose 的节点。

它的原理是从当前速度、输入方向、朝向、加速度和移动模型推演若干未来点，并以同一坐标空间保存过去点。查询时，候选动画根运动轨迹与这些点逐点比较；误差小的动作更符合当前意图。预测每帧突然改向时，数据库再完整也会不断重选。

典型应用是输入向右时提前选右转跑步姿势，松开输入时选减速 / 停止姿势，急转时选择正确支撑脚相位。调试先画预测与实际轨迹；不一致时先修输入平滑或移动模型，不要先扩大数据库。

## Chooser：用上下文缩小可选资源

Chooser 是规则表驱动的对象选择框架，可根据动画实例或玩法上下文返回 Animation、Montage、Pose Search Database 等资源，但不混合 Pose、也不计算 IK。

它的原理是表列读取 Context Object、Gameplay Tag 或字段值，条件筛选后由结果列返回对象。它将“Falling 时不查地面数据库”“持双手武器时改用专用数据库”从散落的 `if / switch` 收拢为规则。输入状态的更新时序若和查询不同步，结果会滞后一帧或频繁抖动。

典型应用是在 Motion Matching 查询前按移动模式、姿态、步态与武器状态限制 Database；或按玩法状态选择 Montage。先固定 Database 验证历史和轨迹，再打开 Chooser 验证规则，能分清检索错误与规则错误。

## Proxy Table：将逻辑引用解析为变体资源

Proxy Table 是资源间接引用机制。调用处引用一个 Proxy，而非直接硬引用某个具体动画、数据库或其他资产。

它的原理是运行时按上下文将 Proxy 映射为最终对象，集中表达“同样是 Run Database，但不同体型、武器或风格要用不同版本”的变体规则。Chooser 偏向条件选择，Proxy 偏向资源替换；两者可组合。

典型应用是多角色共用一张动画图但替换各自的 Database / Montage，或按武器、体型、平台映射等价资源。资源不会随上下文改变时，直接引用更易读；它的价值是避免复制图与硬引用散落，不是让动画选择更智能。
