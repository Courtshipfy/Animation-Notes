# 动态姿势过渡：Blend Stack、Inertialization、Dead Blending

> 选择系统回答“接下来用哪个姿势”，过渡系统回答“怎样带着当前运动趋势到达它”。它们不能修复错误选择。

## Blend Stack：管理持续重定向的姿势流

Blend Stack 是面向动态姿势流的混合基础设施，为连续进入的候选动画维护混合记录，适合 Motion Matching 随时改选另一段动画的情况。

它的原理是每次上游给出新候选时，不退化成固定 A / B 状态，而是保留当前混合上下文并建立下一段过渡，因此能承受频繁重定向。Game Animation Sample 的 Motion Matching Blend Stack Graph 还承载 Orientation Warping 与 Steering，让修正作用于每个候选姿势。它不判断候选是否正确。

典型应用是数据库连续切换跑步、转向、停止片段的现代 Locomotion。若只有少量固定状态跳转，普通 Blend 和状态机更直接；无需为了它重写稳定状态机。每个候选都应经过的姿势修正可放入其 Graph，避免内外层重复处理方向或根运动。

## Inertialization：保留切换瞬间的速度趋势

Inertialization 是惯性式姿势过渡节点。它不在整个混合期持续计算来源 Pose，而在切换瞬间记录骨骼变化趋势，再让与新 Pose 的差异逐渐衰减。

它的原理是收到 Inertialization Request 时采样骨骼的位置、旋转及其变化速度，输出成为“新 Pose + 逐帧衰减的旧运动残差”。手、脚、脊柱不会突然从旧速度归零，来源动画也可不再持续评估。State Machine Transition 的 Blend Logic 或 AnimGraph 显式请求触发它；没收到请求就不会生效。

典型应用是昂贵动作、频繁状态切换、或 Aim Offset 等不断改变目标姿势的层。节点应放在请求能到达的输出路径，常位于 State Machine / Blend List 之后；时长过短会 Pop，过长会拖着旧动作。先观察手脚和根骨的速度连续性，再叠加 Warping、IK。

## Dead Blending：用曲线塑造动态层的残差衰减

Dead Blending 是 Game Animation Sample 使用的较新惯性式动态过渡方案，支持 Blend Curve 控制衰减形状；其节点形态和可用性随 UE5 版本而定。

它的原理是和 Inertialization 同样使用切换时的运动残差，而非持续对来源 / 目标 Pose 进行普通线性混合；不同之处是可用曲线塑造残差消失速度，以适应快速起效、慢速收尾等动态层节奏。

典型应用是示例中反复启停的 Aim Offset 等动态姿势层。应先以 Inertialization 建立基线，确认问题在过渡而不是姿势选择、Warping 或 IK；再核对目标引擎版本的节点与插件。它不是“修复数据库误选”的工具。
