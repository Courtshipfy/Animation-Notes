# 接触与 IK：Foot Placement、Leg IK、Full Body IK

> 接触系统决定末端目标，IK 系统决定骨骼怎样响应。三者在同一链路中协作，却不是彼此替代的版本。

## Foot Placement：把脚部接触当成连续状态

Foot Placement 是 Animation Warping Runtime 的高级脚部放置节点。它为每只脚维护可落脚的位置、朝向与支撑状态，并在需要时调整骨盆；不是“一条射线 + Two Bone IK”的别名。

它的原理是把腿部定义、动画脚部运动、角色与地面的关系，以及脚的 Plant / Swing 状态一起用于计算脚掌目标。支撑阶段尽量维持接触，摆动阶段平滑释放并寻找下一落点；双腿高度冲突或腿长不足时，以骨盆补偿为腿链腾出可达空间。它同时处理脚何时锁定、何时离地和双脚不等高时身体怎样让位。

典型链路是胶囊驱动 Locomotion 在斜坡、台阶和轻微不平地面的最终接触层：`基础移动 Pose → Pose Warping（可选）→ Foot Placement`。已有 Foot Lock、Foot Offset、Pelvis Offset 的项目，应逐层替换相同职责；旧 Foot Lock 与它同时锁同一只脚，常造成吸附与双重补偿。

## Leg IK：执行已经确定的脚部目标

Leg IK 是 AnimGraph 的 Skeletal Control。上游给出 IK Foot Bone 或目标脚骨的 Transform 后，它沿大腿—小腿—脚链条调整关节，让末端尽量到达该目标。

它的原理是局部链求解：一个脚部目标只约束对应腿，解算器在腿长、关节方向与限制允许的范围内重分配髋、膝、踝旋转。目标不可达时，腿不会无条件拉长，因此骨盆高度、目标距离和膝盖初始朝向仍是上游责任。它只回答“怎样够到”，不回答“脚该踩哪里”。

典型链路是 `Trace 或 Foot Placement 决定 IK Foot → Pose Warping 修正整体步态 → Leg IK 回写实际腿链`。这样可将接触决策和腿链执行分开调试。把未平滑的实时 Trace 直接送入它，角色移动或地面法线跳变时往往脚滑、抖动。

## Full Body IK：让多个末端共同影响全身

Full Body IK（FBIK）是 Control Rig Graph 中的全身求解节点，基于 Position Based IK（PBIK）。它可同时处理脚、手、头等多个 Effector，不是普通 AnimGraph 腿节点。

它的原理是让每个 Effector 提出期望的末端位置或朝向；求解器从指定 Root 向各条链传播影响，并迭代让骨盆、脊柱和四肢共同折衷。Position / Rotation Stiffness、Preferred Angle 与 Rotation Limit 决定哪些骨骼让位、哪些姿势保留；关键是正确分配身体响应，而非盲目提高权重。

典型应用是双脚在不同高度、双手还要扶物体，攀爬时手脚同时约束，或与环境发生全身交互。动画蓝图通常经 `Control Rig` 节点运行含 FBIK 的 Rig。只需把单脚接到目标时 Leg IK 更简单；全骨架和无关 Effector 都参与求解，反而容易出现不需要的肩膀、脊柱与骨盆代偿。
