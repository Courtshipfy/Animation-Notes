# Orientation Warping 详解

> Orientation Warping 做的事一句话就能说清：让下半身朝着实际移动方向转过去，同时让上半身尽量保持原来的面向。它的聪明之处在于，不真的去「旋转角色」，而是算出这一帧该掰多少度，再把这笔旋转用「正反抵消」的方式摊到几组骨骼上。

## 它解决的问题

假设你只有一段向前跑的循环动画。动画里脚踩的方向、根运动的方向，都锁死在「动画的正前方」。现在角色斜着走——比如手柄往左前 30° 推，胶囊拖着身体朝左前移动，但动画的步态还朝着正前。结果就是脚往前迈、身体往斜里滑，下肢步态和真实位移方向错开，看起来像在冰面上打滑。

Orientation Warping 就是来补这个「方向残差」的：它测量「动画这帧实际在朝哪走」和「角色想朝哪走」之间的夹角，然后把下肢掰过去对齐。

它明确**不做**三件事，理解了边界才不会误用：

- **不选动画**：它不能把一段向前跑变成真正的左转跑，只是把现有姿势掰一掰。大角度后退、纯横移，还得靠对应资产（或方向 Blend Space）。
- **不驱动 Actor 转向**：Manual 模式下它只改姿势，胶囊该怎么走还怎么走。
- **不算 IK**：它只动 IK 脚的目标位置和朝向，真正把大腿—小腿—脚解算回腿链，是后面 Leg IK 的活。

## 核心思想：只算一个残差角，再分摊掉

整个节点的求解可以浓缩成两步：

1. 算出一个**有符号角度** A——「动画这帧的移动方向」相对「角色想要的移动方向」差多少。
2. 把这笔旋转 A 按比例摊给四组骨骼，用正转、反转相互抵消，达到「下半身整体转 A、上半身整体不转」的效果。

分摊的规则是一条恒等式（设 `A` 是总旋转角，`d` 是分配比例，默认 0.5）：

| 骨骼组 | 旋转量 |
|---|---|
| 根骨 | `+A · d` |
| 脊柱 | `−A · d`（合计） |
| IK 脚根 | `+A · (1−d)` |
| IK 脚 | `−A · (1−d)`（合计） |

代入默认 `d = 0.5` 就能看出妙处：

- 根骨是全身所有骨骼的祖先，转它 `+A/2` 等于把**整个身体**便宜地转了半圈残差；
- 脊柱再反向转 `−A/2`，恰好抵消掉根骨带来的旋转，于是**上半身净转 0**，保持面向；
- IK 脚根（下半身的参考空间）再转 `+A/2`，把脚的整体朝向补满，于是**下肢净转 A**；
- IK 脚本身反向转 `−A/2`，抵消掉脚根对脚朝向的影响——脚的世界朝向不变，只是位置跟着被挪动。

一句话：**下肢跟着移动方向转满 A，上半身转 0，中间用脊柱平滑过渡**。`d` 越大，身体（根骨+脊柱）这条路径承担越多、IK 脚根承担越少；`d` 越小，压力越往脚上压。

### 脊柱权重为什么必须是「每条路径和为 1」

脊柱的反向补偿是「每根骨头各摊一点」。配置里给的是从 `spine_01` 到 `spine_03` 的一串骨头，初始化时会给它们分权重：单条链三根骨头就各得 1/3；如果在链尾又接了 `neck`、`head`，那 `neck` 分权重时发现 `spine` 已经占掉 1/3，就把剩下的 2/3 在 `{neck, head}` 之间继续均分。

这样做的目的很明确：**保证从根骨到任何一根脊柱骨的路径上，权重加起来恒等于 1**。否则脊柱反向转的总量就不是严格的 `−A·d`，上半身要么残留一点偏转、要么被过度掰回来。

## 它怎么判断「该转多少」

求那个残差角 A，有两种模式。

### Manual：直接给角度

最简单的情况——你在节点引脚上直接给一个 `OrientationAngle`（比如用 `CalculateDirection` 算出胶囊速度相对 Actor 朝向的角度），节点就按这个角掰。适合想自己完全掌控修正量、或者没有走根运动属性流的场景。

### Graph：从根运动方向和移动方向反推

现代 Locomotion（尤其 Motion Matching）默认用 Graph 模式。它的输入是「动画这帧往哪走」和「角色想往哪走」两个方向，角度由两者之差得出：

```text
A = 有符号夹角( 动画本帧根运动方向, 角色移动方向, 旋转轴 )
```

所谓「有符号」，就是点积求角度、叉积与旋转轴点积定正负，于是能区分「偏左」还是「偏右」。

**Graph 模式有一个关键副作用**：它不只在姿势上掰，还会把上游传下来的根运动**一起旋转 A**，写回属性流。这意味着胶囊的实际位移会跟着被掰过去——角色真的朝修正后的方向走。这是它和 Manual 最本质的区别：Manual 只动姿势，Graph 连「身体往哪走」都一起改。

要读懂 Graph 模式，有三个容易踩的坑值得单独讲：

1. **坐标系校正**。角色的 Actor 正前方和骨骼网格组件的正前方往往不一致（历史原因，网格可能相对 Actor 有旋转）。所以节点不会傻乎乎地直接拿世界空间的移动方向去和根运动方向比，而是先把移动方向转到组件空间（或你指定的 Warping Space）再比。配错了参考空间，算出来的 A 就偏了。
2. **没有根运动就不掰**。起步、停止、待机这些帧，动画根本没有根运动位移，也就没有「方向」可言。此时强行掰只会把姿势扭坏。所以节点设了一个速度门槛：根运动速度低于阈值时，目标角直接归零，交给平滑慢慢回落。
3. **方向差太大就反转**。Motion Matching 偶尔会选出方向偏差很大的动画——比如你正后退，它却给了几帧向前跑的动画。这时「动画方向」和「移动方向」几乎差了 180°，与其把下肢硬掰 180° 拧成麻花，不如认为「动画其实在朝反方向表达」，当成 0° 处理。节点就是靠「夹角超过 90° 就补 180°」这个规则来拦截这种极端情况的。

## 平滑与「反向补偿」

算出来的 A 是「目标角」。如果每帧直接跳到目标角，遇到方向突变会 Pop；所以节点用插值让实际角慢慢追目标角。

但这里藏着一个容易忽视的细节：**动画自己每帧也在转身**。根运动方向不是固定的，它在随动画自然变化，这个自然转角其实已经包含在目标角里了。如果插值器再对它平滑一遍，就会「和流经图表的自然根运动打架」——表现为转向时下肢一顿一顿。

解决办法叫**反向补偿**：先把「根运动这一帧自己转了多少」单独拎出来，这部分**原样保留**，插值只对剩下的「残差」做平滑，最后再把两部分拼回去。效果就是：动画自然的转身不被打断，插值只负责消化「姿势方向」和「移动方向」之间的那点真实误差。

同时，如果根运动单帧转角超过一个上限（比如 45°），大概率是 pivot 或一次糟糕的混合，这时就不补偿，交给插值去平滑掉。

## 它不碰什么、和谁配合

Orientation Warping 是链路里的一环，放对了才有效：

- **后面必须接 Leg IK**。Orientation Warping 只改 IK 脚的目标（位置和朝向），从不碰大腿—小腿—脚的实际骨骼链。要把被掰过的 IK 脚目标落实成真实腿姿，得靠 Leg IK 解算回去。
- **参考空间可以跟随 Offset Root Bone**。当你用了 Offset Root Bone 让网格根骨和胶囊短暂分离时，移动方向应该相对「根骨当前姿势」来算，而不是相对组件。节点通过图消息从 Offset Root Bone 拿到根骨变换作为参考空间；没有这个节点就退回组件空间。
- **常驻 Motion Matching 内层**。它一般放在 Motion Matching 的 Blend Stack Graph 里，对每个被选中的候选姿势统一做方向修正。放内层（而不是主 AnimGraph 再叠一层）能避免对同一对象掰两次。

## 常见问题

- **节点「没反应」**：绝大多数情况不是角度没给对，而是**配置不完整**——脊柱、IK 脚根、IK 脚三组骨骼缺一个，节点会直接静默失效（因为没了分摊的对象，它就没有意义）。先查配置，别急着怀疑引脚。
- **Graph 模式角色不转身**：Graph 模式的前提是上游真的写了根运动属性。如果上游不是 Motion Matching 或没开 Root Motion 的 Sequence Player，节点取不到根运动就 early-return。另外确认 `Mode` 真的是 Graph（默认是 Manual）。
- **起步/停止瞬间下肢乱扭**：这是无根运动帧在作怪。速度门槛把目标角归零了，但如果还扭，检查阈值是否太小、以及平滑速度是否留了足够时间让角度归零。
- **前进动画配后退移动，下肢被掰 180°**：应该是 90° 反转规则没拦住，确认该阈值 > 0、且移动方向输入正确。
- **转向时一顿一顿**：优先怀疑反向补偿被关掉或阈值太小，导致插值器和自然根运动打架。
