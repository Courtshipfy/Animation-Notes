# 相机系统概览与 3C 定位

> 相机是 3C 中独立于角色动画的一环，负责把「玩家看哪里」（Control Rotation）与「角色朝哪里」（角色朝向）分开。

## 解决的问题

UE 默认第三人称模板用 SpringArm + Camera 挂在角色身上：相机朝向跟随角色朝向，鼠标转动角色、相机被动跟随。这对「角色始终面向移动方向」的简单玩法够用，但当角色需要独立于视角移动（侧移、后退、瞄准）时，相机跟随角色朝向会让取景不稳定，也会把胶囊体的抖动直接传到画面。

3C 玩法的核心诉求是：角色朝向（Character 的移动/瞄准方向）与相机朝向（Camera 的取景方向）由不同输入驱动、可以独立变化。ALS 因此没有直接套用模板相机，而是自研了一套第三人称相机。

## 3C 中的职责边界

| 部分 | 职责 | 主要输入 / 状态 |
| --- | --- | --- |
| Character | 移动、朝向、姿态 | 移动输入、RotationMode、Stance、Gait |
| Camera | 取景、跟随、防穿墙 | Control Rotation、相机距离 / 高度 / FOV |
| Control | 把玩家输入转成旋转 | 鼠标 / 摇杆 → Control Rotation |

相机的 Control Rotation 是三者交汇的关键：它由玩家输入驱动、决定相机朝向，同时作为角色动画侧 `ViewState` 的输入，反过来影响脊柱和头部姿势。

## ALS 的两条实现线

| | ALS v4 / Community | ALS Refactored |
| --- | --- | --- |
| 载体 | 自定义 `APlayerCameraManager`（蓝图 `ALS_PlayerCameraManager`，C++ 版 `ALSPlayerCameraManager`） | 挂载在角色上的 `UAlsCameraComponent` + `UAlsCameraSettings` 数据资产 |
| 计算入口 | 重写 `CustomCameraBehavior` | `TickComponent` 分阶段计算，`GetViewInfo` 输出 POV |
| 相机位置归属 | 全局相机管理器，与具体角色解耦 | 相机组件随角色走，天然跟随角色 |

两者机制一致：都以 Control Rotation 为视角来源，通过「锚点 + 旋转/位置延迟 + 防穿墙」生成最终相机变换。差别主要在组织方式：v4 把逻辑放在全局管理器，Refactored 把它收进角色组件，并用数据资产集中管理可调参数。

## 关键解耦点

相机与角色解耦的本质是：**相机的目标旋转来自 Control Rotation（玩家输入），而不是角色朝向**。于是：

- 角色可以朝向速度方向奔跑，相机却稳定看向玩家想看的方位。
- 瞄准时角色朝向被限制在视角附近（Aiming Rotation），但相机本身仍由鼠标直接控制。
- 转动相机不会带动角色转身，除非 RotationMode 要求角色对齐视角（ViewDirection）。
