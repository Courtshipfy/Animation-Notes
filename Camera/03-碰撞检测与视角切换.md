# 碰撞检测与视角切换

> 相机在靠近墙角时自动拉近、在第一/第三人称间平滑切换，是自研相机相对模板最直接可感知的两个能力。

## 防穿墙 Trace

第三人称相机在角色背后，容易穿过墙壁或进入遮挡物内部。处理方式是：从锚点向期望相机位置做射线检测，命中遮挡物时把相机拉近到命中点并留一点余量。

- 使用专门的 `CameraTraceChannel`（默认常用 Visibility），并把角色自身（Pawn / 所有者）从检测中忽略，避免相机被角色胶囊体挡住。
- 拉近后的相机位置仍经过位置延迟，因此不会瞬间跳变。
- ALS Refactored 把检测参数（半径、通道、余量）放进 `UAlsCameraSettings`，使用球体或射线追踪。

这正是 UE SpringArm `DoCollisionTest` 的自制等价物，差别在于 ALS 自己控制命中后的位置和余量，便于配合它自己的延迟逻辑。

## 第一 / 第三人称切换

切换时相机目标位置从「锚点 + 偏移」换成角色头部 / 眼睛 Socket 的世界位置，FOV 在 `ThirdPersonFOV` 与 `FirstPersonFOV` 之间过渡。

- 第一人称下相机不再依赖锚点和偏移，直接跟随头部 Socket，因此会随角色低头 / 抬头和姿态移动。
- 切换本身用延迟或插值平滑，避免 FOV 和位置突变造成眩晕。

## FOV

- 第三人称 FOV 决定取景范围和角色在画面中的大小；第一人称 FOV 决定代入感。
- ALS Refactored 的 `CameraFov` 可被外部逻辑或动画驱动（例如冲刺时略微放大 FOV 制造速度感），v4 也保留 FOV 过渡。

## 调试

两类实现都带调试可视化，用于确认相机计算是否符合预期：

- 绘制锚点（Pivot）、期望位置、实际位置和 Trace 线段。
- 开启 `DebugView` / `TraceDebug`（v4）或 Refactored 的调试选项后，命中点、拉近后的位置会以不同颜色标出。

调防穿墙和延迟时先开调试，确认是 Trace 命中错误还是延迟参数过大，再改参数。
