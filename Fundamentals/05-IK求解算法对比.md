# IK 求解算法对比：TwoBone / CCD / FABRIK

> 所有 IK 求解器都回答同一个问题——给一条骨链和一个末端目标，这条链该怎么摆才能让末端到位。真正的差别在三点：用什么方式算、解出来的姿态长什么样、能容忍什么约束。分清「解析解 vs CCD vs FABRIK」这三种路子，才能在 TwoBoneIK、CCDIK、FABRIK、Leg IK 这些节点之间不选错。

## 它解决的问题

动画里骨链默认按 FK 摆着，末端（手、脚）落在哪由每一级父骨头的旋转累积决定。一旦末端必须对准某个外部目标（手抓武器、脚踩地面、尾尖触到某个点），直接改某几级旋转往往牵一发动全身。IK 求解器就是「给定末端目标，反推出整条链的旋转」的算法。

不同场景对求解器的要求不一样，所以不存在唯一最优：

- 两骨链（上臂+前臂、大腿+小腿）要求快、稳、一次到位；
- 多骨长链（尾巴、触手、脖子、整条手臂）要求解出来的姿态自然、别在某几节突然折；
- 机械臂、需要精确角度上限的关节，要求能直接夹住每个关节的旋转范围。

这三种诉求分别对应三条技术路线：解析解、CCD、FABRIK。它们不是「哪个更强」的排行，而是「不同约束下谁更合适」的取舍。

## 三条技术路线

### 解析解（闭式解，TwoBone）

只对「根—中—末」三段骨（两个骨节）成立。已知根位置、末端目标、两段骨长，中间关节的位置用余弦定理一次求出：

```text
中间关节 = 根 + 段长 · ( 根→目标方向 · cosθ + 弯曲方向 · sinθ )
```

`θ` 由三边长度反解。全程只有位置运算、一次算完，不迭代，所以最快、最稳。唯一的二义性是中间关节能朝「根-末连线」的两侧各弯一下，需要额外给一个弯曲方向（pole vector / 极向量）或从当前姿势里提取膝盖/手肘现在弯向哪边来定侧。

局限：**只适用两骨链**。超过两骨，三边关系不成立，必须换迭代法。

### CCD（循环坐标下降）

迭代法，操作对象是**每个关节的旋转角度**：

1. 从末端关节开始，朝根方向逐个处理；
2. 每个关节只转一次，让「该关节 → 末端」向量尽量对准「该关节 → 目标」向量；
3. 重复迭代，直到末端误差小于阈值或到达迭代上限。

优点：实现最简单、每步成本最低，而且因为直接在角度空间操作，**给关节夹角度上限是顺手的事**（转完 clamp 一下即可）。UE 的 CCDIK 节点（`FAnimNode_CCDIK` / Control Rig 的 `FRigUnit_CCDIK`）就带 `bEnableRotationLimit` 和逐关节的旋转限制。

缺点：从末端往根转，旋转天然**堆积在靠近末端的关节**上，姿态看起来像手腕/脚踝处突然折一下，不自然；链越长，末端误差收敛越慢。

### FABRIK（前向后向到达）

迭代法，操作对象是**位置（点）**而不是角度：

1. 前向：把末端点直接放到目标上，再沿链往回走，把每个点按「段长不变」反推回根；
2. 后向：把根点放回原处，再朝末端顺推，重新摆正各点；
3. 两个方向交替，直到末端与目标的距离小于阈值、或到达迭代上限。

优点：弯曲被**均匀分摊到整条链**，姿态自然；收敛比 CCD 快；目标超出最大臂展时，有清晰的「整条链伸直指向目标」行为。

缺点：它不直接算出角度，**想加「某关节最多转 X 度」这类限制，得把位置反解回角度再夹**，比 CCD 麻烦得多。这是 FABRIK 公认的主要短板。

## CCD vs FABRIK：为什么 FABRIK 更常被首选

两者同属「迭代启发式」求解，但性格完全不同：

| | CCD | FABRIK |
|---|---|---|
| 操作对象 | 角度（逐关节旋转） | 位置（逐点前推/后拉） |
| 姿态分布 | 偏向末端，观感硬 | 均匀分摊，观感自然 |
| 收敛速度 | 长链慢 | 快 |
| 角度限制 | 直接 clamp，简单 | 需反解回角度，麻烦 |
| 实现难度 | 最简单 | 简单 |

结论：**角色动画里 FABRIK 更流行，是因为它「默认好看且快」；CCD 不是不能用，而是默认姿态质量吃亏**。CCD 的优势在「精确夹角度」和「实现极简」，所以机械臂、需要硬角度上限、或只想把末端凑到位而不在乎中间形状时仍有价值。真要解两骨臂/腿，两者往往都不如解析解直接。

## UE 里的节点怎么对应

理解「算法 → 节点」的映射，就不会把 CCDIK 和 Leg IK 当成一回事：

| UE 节点 | 内核 | 定位 |
|---|---|---|
| Two Bone IK（`FRigUnit_TwoBoneIK`） | 解析解 | 两骨链专用，配 pole vector 控肘/膝方向 |
| CCDIK（`FAnimNode_CCDIK`） | CCD | 裸的通用迭代求解器，可夹逐关节角度 |
| FABRIK（`FAnimNode_Fabrik`） | FABRIK | 裸的通用迭代求解器，姿态自然 |
| Leg IK（`FAnimNode_LegIK`） | 两骨闭式解 + FABRIK 兜底 | 脚部贴地的**功能节点**，不是裸求解器 |
| Full Body IK（`FRigUnit_PBIK`） | Position Based 约束求解 | 另一种家族，多 Effector 全身折衷 |

最容易混淆的一对是 **CCDIK vs Leg IK**。它们都算 IK，但：

- CCDIK 是「通用算法节点」，跟 FABRIK、Two Bone IK 平级，是纯求解器；
- Leg IK 是「脚步贴地功能节点」，内部链求解走的是**两骨闭式解（默认）+ 长链退回 FABRIK**，根本不用 CCD；节点本身还额外叠加了贴地、骨盆、腿部伸缩等一整套脚步逻辑。

所以「CCDIK 和 Leg IK 理念差不多」只对了一半：它们同属 IK 大家族，但 Leg IK 的核心求解不是 CCD，且它是个「成品」，比 CCDIK 多了整层脚部策略。

（Leg IK 的两骨/FABRIK 切换受控制台变量 `a.AnimNode.LegIK.EnableTwoBone` 控制，求解入口是内部的 `FIKChain::ReachTarget`。）

## 怎么选：决策顺序

```text
1. 链有多长？
   ├─ 两骨（臂/腿）      → Two Bone IK（解析解，最快最稳）
   └─ 多骨长链           → 进入第 2 步
2. 在意姿态是否自然？
   ├─ 在意               → FABRIK
   └─ 只求末端到位 / 必须精确夹关节角度 → CCDIK
3. 是不是「脚踩地」这类专门需求？
   ├─ 是                 → Leg IK（自带 TwoBone/FABRIK + 贴地策略）
   └─ 多末端全身折衷      → Full Body IK (PBIK)
```

关键原则：**先按链长选求解器，再按「是不是专门功能」决定要不要上功能节点**。单脚贴地不必上 Full Body IK，多骨链不必硬套 Two Bone IK，需要精确角度上限时才想起 CCD。

## 常见问题

### 把 Leg IK 当 CCDIK 用，或反过来

Leg IK 是「脚部贴地」功能节点，它内部会自行解算腿链（两骨/FABRIK），不需要也不应该再串一个 CCDIK 去解同一条腿。CCDIK 是通用求解器，没有贴地、骨盆、伸缩这些语义，拿它做脚步贴地得自己补一整层上游逻辑。

### 多骨链用了 Two Bone IK，末端永远差一截

Two Bone IK 只认两骨。给一条三骨以上的链，它要么按配置截取、要么根本解不对。超过两骨就该换 FABRIK 或 CCDIK。

### FABRIK 解出来的肘/膝反着弯

FABRIK 基于位置，不天然知道「关节该往哪侧弯」，需要额外机制定弯曲方向（如偏好角度、极向量或从源姿势提取）。不是 FABRIK 坏了，是缺弯曲方向约束。

### 需要「关节最多转 X 度」却上了 FABRIK

角度限制在 FABRIK 里要反解回角度再夹，麻烦且可能破坏收敛。这种需求优先选 CCDIK（原生逐关节角度限制），或换 Full Body IK（有显式 Rotation Limit）。

### 两骨链上 CCDIK/FABRIK 也能解，但没必要

能解不代表该用：解析解一次到位、零迭代、无收敛抖动，两骨场景没有任何理由用迭代法去替代它。
