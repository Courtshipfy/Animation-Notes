# 姿态叠加与动画分层

> 姿态叠加的本质是让多个动画来源各自负责身体的一部分或姿势变化的一部分，再通过明确的权重、骨骼范围和执行顺序合成为最终骨骼姿势。

## 解决的问题

角色通常需要同时表达多件事情：下半身正在跑步，上半身保持持枪姿势，脊柱跟随瞄准方向，手部对齐武器，脚部贴合地面，并且还可能临时播放换弹或受击动画。

如果为每一种组合制作完整动画，资产数量会迅速膨胀：

```text
跑步 × 持枪 × 向上瞄准 × 换弹 × 斜坡
```

动画分层将它拆成可以复用的职责：

```text
基础 Locomotion
    + 装备或姿态层
    + Aim Offset
    + Montage / Slot 动作
    + 手脚 IK
    = 最终姿势
```

“持枪”只是典型例子。同一套机制也可以处理受伤姿势、搬运物体、举盾、蹲伏上半身、呼吸、后坐力、表情和局部受击。

## 动画图中到底在混合什么

一个 Pose 主要包含当前骨架中各骨骼的变换。动画节点还可能同时传递动画曲线、Root Motion 和 Attributes，因此姿势叠加不只是把几个骨骼旋转相加。

每一层都应该回答四个问题：

1. 输入的基础姿势是什么？
2. 这层修改哪些骨骼、曲线或 Root Motion？
3. 修改是替换还是增量？
4. 结果还会被哪些后续节点修改？

只看到“某个 Alpha 为 1”并不能证明这层一定生效。如果后面的层再次覆盖相同骨骼，前面的结果仍会消失。

## 四种主要组合方式

### 全身 Override

全身 Override 使用另一张完整姿势替换或混合当前姿势。例如角色从普通 Locomotion 切换到攀爬、游泳、完整受击或处决动作。

```text
FinalPose = Blend(BasePose, OverridePose, Alpha)
```

它适合动作需要控制全身和 Root Motion 的情况，但会覆盖基础移动中的脚步、骨盆和身体方向。若动作只影响局部身体，使用全身 Override 往往会损失不必要的信息。

### 局部 Override

局部 Override 只让某些骨骼采用另一张姿势。典型实现是 `Layered Blend Per Bone`、Branch Filter 或 Blend Mask。

例如从 `spine_01` 开始覆盖所有子骨骼：

```text
腿部、骨盆 → 保留 Locomotion
脊柱、手臂、头部 → 使用 Weapon Pose
```

局部 Override 不是“只混合选中的一个骨骼”。骨骼层级会决定影响范围；从脊柱开始通常会影响胸口、肩膀、手臂、颈部和头部。若起始骨骼选得过低，武器姿势会修改骨盆甚至腿部；选得过高，则肩膀和上臂无法正确进入姿势。

Branch Filter 通过起始骨骼和 Blend Depth 描述范围，Blend Mask 则在 Skeleton 资产中为每根骨骼保存权重。前者方便快速配置，后者适合复用复杂且稳定的身体区域。

### Additive

Additive 不提供完整目标姿势，而是保存相对于参考姿势的变化量：

```text
FinalPose = BasePose + AdditiveDelta × Alpha
```

适合 Additive 的内容包括：

- Aim Offset；
- 呼吸和轻微身体摆动；
- 后坐力；
- Lean；
- 轻度受击和姿势风格修正。

Additive 最重要的不是节点，而是参考姿势。动画资产记录的是“当前姿势相对哪一帧发生了什么变化”。如果 Base Pose Animation、参考帧或骨架不匹配，即使 Alpha 很小也会出现肩膀抬高、手臂扭曲或身体整体偏移。

常见空间包括：

- Local Space Additive：变化沿父子骨骼的局部空间累积，适合大多数局部姿势变化；
- Mesh Space Additive：旋转相对 Skeletal Mesh 组件空间表达，前置骨骼如何旋转都不会改变增量的世界感方向，常用于 Aim Offset。

### Montage / Slot 插入

Slot 是动画图为 Montage 预留的插入位置。Montage 决定播放什么、何时播放和如何分段，Slot 决定这段动画在最终动画图的哪一层出现。

Slot 名为 `UpperBody` 并不会自动只影响上半身。它仍会输出完整姿势，必须再经过 `Layered Blend Per Bone` 或对应 Anim Layer，才能限制骨骼范围。

常见用途包括：

- 射击、换弹和近战攻击；
- 交互和拾取；
- 受击反应；
- 需要 Notify、Section 和可中断控制的临时动作。

Montage 更适合有明确时间流程的事件动作，持续性的持枪站姿通常更适合由状态、动画层或姿势资产维持。

## Aim Offset 是特殊的 Additive Blend Space

Aim Offset 使用 Yaw、Pitch 等参数在多个 Additive Pose 之间插值，再把结果叠加到基础瞄准姿势。官方要求 Aim Offset 样本使用 Mesh Space Additive，原因是瞄准旋转需要相对 Skeletal Mesh 保持一致，而不能随着父骨骼局部轴发生偏转。

典型链路是：

```text
Locomotion
    ↓
Weapon Base Pose
    ↓
Aim Offset(Yaw, Pitch)
    ↓
Hand IK
```

Aim Offset 不负责角色 Actor 转向。角色旋转系统决定身体整体朝向，Aim Offset 只表现视角与身体之间剩余的相对角度。如果允许 Aim Yaw 无限增大，脊柱和肩膀会扭到不自然范围，因此通常需要和 Turn In Place、Rotation Mode 或视角角度限制配合。

## Linked Anim Layer 解决的是模块边界

Linked Anim Graph 和 Linked Anim Layer 主要解决复杂动画蓝图的拆分、替换和按需加载问题。它们本身不等于 Additive 或骨骼遮罩。

Animation Layer Interface 可以定义类似下面的契约：

```text
FullBodyLayer() -> Pose
UpperBodyLayer(InputPose) -> Pose
IkLayer(InputPose) -> Pose
```

基础 Animation Blueprint 只规定调用顺序，具体装备或角色类型提供各层实现：

```text
Full Body → Upper Body → IK
```

这种设计特别适合：

- 不同武器替换不同上半身逻辑；
- 不同角色体型替换动作集；
- 基础 Locomotion 保持不变，只更换装备层；
- 将大型 AnimBP 拆成可以独立加载和维护的资源。

是否使用 Linked Anim Layer 和“最终怎样混合骨骼”是两个问题。层内部仍可能使用 Additive、Layered Blend Per Bone、Slot 或 Control Rig。

## Alpha 和遮罩从哪里来

一层姿势通常不会永远以完整权重生效。它的 Alpha 可能来自：

- Gameplay 状态，例如 Armed、Aiming、Injured；
- 动画曲线，例如某个动画阶段允许手臂或 IK 生效多少；
- Montage Blend In / Blend Out；
- Anim Layer 的输入参数；
- 速度、视角角度、Grounded Amount 等连续参数；
- 惯性过渡或 Dead Blending 的衰减结果。

动画曲线特别适合表达“当前动画知道的信息”。例如换弹动画可以在弹匣接触期间降低左手 IK，而不是由游戏代码猜测具体时间。

需要区分两种权重：

- Layer Alpha：整层对最终姿势有多大影响；
- Bone Weight：这层对某根骨骼有多大影响。

最终影响通常是两者共同作用的结果。

## 执行顺序为什么重要

没有一条适合所有项目的唯一顺序，但下面是一条常见主线：

```text
1. 基础 Locomotion / Motion Matching
2. 步态、方向、Lean 和姿势风格修正
3. 装备或持续性 Upper Body Layer
4. Aim Offset
5. Upper Body / Full Body Montage Slot
6. Hand IK、Foot IK、Foot Placement、Control Rig
7. 最终后处理
```

这个顺序背后的原则是：先选择和组织动画姿势，再执行必须精确对齐目标的 IK。

例如左手 IK 应读取武器和右手经过持枪姿势、Aim Offset、后坐力或换弹动作之后的位置。如果先锁定左手，后面的 Aim Offset 又旋转了脊柱和右臂，左手仍可能离开武器。

Slot 的位置取决于动作意图：

- 射击 Montage 若包含后坐力，可以放在 Aim Offset 之后，让动画直接覆盖部分瞄准结果；
- 若希望 Aim Offset 始终控制最终枪口方向，可以让 Aim Offset 在射击 Slot 后继续修正；
- 全身 Root Motion Montage 往往需要绕过普通 Upper Body 分层，直接控制完整姿势。

因此应该为每个 Slot 明确它插入在哪一层，而不是只按动作名称创建大量 Slot。

## 一个持枪姿势的完整例子

```text
Grounded / InAir 基础移动
        │
        ├─ Armed 状态选择 Rifle Upper Body Pose
        │
        ├─ 从脊柱开始局部 Override 或 Additive
        │
        ├─ Aim Offset 调整瞄准方向
        │
        ├─ Fire / Reload Montage 通过 UpperBody Slot 插入
        │
        ├─ 动画曲线控制左手 IK、手指和局部层权重
        │
        └─ Hand IK 将左手最终对齐武器 Socket
```

需要注意，持枪基础姿势可能采用不同方案：

- 普通 Locomotion 上叠加上半身持枪 Pose；
- 使用专门的 Armed Locomotion 全身动画；
- 下半身复用 Locomotion，上半身来自独立 Linked Anim Layer；
- Motion Matching 使用 Armed 数据库，同时再叠加 Aim Offset 和 Hand IK。

这些方案没有绝对优劣。武器对骨盆、肩膀和整体重心影响越大，就越需要专门的全身动画；只改变手臂和胸口时，上半身分层复用性更高。

## 系统专题应该继续回答什么

公共基础只说明工具和原则，具体系统笔记必须继续核对：

- 状态从哪里产生，以 Tag、枚举还是数据资产表达；
- 哪个 AnimInstance 或 Linked Layer 负责更新；
- 实际使用了哪些动画曲线；
- 层的调用顺序和输入输出是什么；
- 武器或姿势资产如何替换；
- Hand IK、Foot IK 和 Control Rig 位于哪一层；
- 哪些结论来自 C++，哪些必须打开动画蓝图资产确认。

因此，不能用本篇替代 ALS、KAI 或 Motion Matching 的实现笔记。

## 常见问题

### Additive 参考姿势不一致

表现通常不是简单的“权重不对”，而是整个肩膀、脊柱或手臂带着固定偏差。检查动画资产的 Additive 类型、Base Pose Animation 和参考帧是否与当前基础姿势约定一致。

### 上半身动作影响腿部

检查 Layered Blend Per Bone 的起始骨骼、Blend Depth 或 Blend Mask。还要检查该层是否携带 Root Motion，或者在局部混合前已经使用完整 Override 覆盖了基础姿势。

### 动画正确，但手没有握住武器

姿势混合只能提供大致姿态。武器 Socket、角色比例和重定向会改变手部最终位置，通常还需要在姿势层之后运行 Hand IK。

### Montage 播放但看不到

检查 Montage 使用的 Slot 是否与动画图中的 Slot 节点一致、Slot 节点是否位于最终输出链上，以及它是否被后面的层完全覆盖。

### Aim Offset 把移动姿势扭坏

检查样本是否是 Mesh Space Additive、参考姿势是否一致、Yaw 范围是否过大，以及 Aim Offset 是否影响了不应参与瞄准的骨骼。

### 同一修正执行了两次

常见于基础 AnimBP 和 Linked Anim Layer 都执行 Aim Offset，或动画层已经包含 Hand IK，主图又再次运行 Control Rig。调试时逐层关闭节点，观察哪一层第一次产生目标结果。
