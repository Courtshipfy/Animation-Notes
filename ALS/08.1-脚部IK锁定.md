# 08.1 脚部 IK 锁定

> Foot Lock 在脚掌支撑地面的阶段保存一个稳定的脚部目标，并持续补偿角色或移动平台的位移与旋转，从而减少原地转身、停止和姿势过渡时的脚滑。

## 解决的问题

动画序列中的脚是相对角色根骨运动的。即使某一帧脚掌看起来踩在地上，只要角色胶囊继续移动、旋转，或者多个动画正在混合，脚骨的世界位置就可能随角色一起漂移。

Foot Lock 的目标是在支撑阶段记住脚当前踩住的位置和朝向，并把后续动画计算得到的脚部目标拉回这个锚点。它主要解决水平方向滑动和朝向漂移，不负责检测地面，也不负责让脚贴合斜坡。

## 完整数据流

```text
动画序列中的脚部曲线
    ├─ FootLeftIk / FootRightIk       → 这只脚是否允许使用 IK
    └─ FootLeftLock / FootRightLock   → 何时捕获、保持和释放锁点
                         │
游戏线程读取脚部 Socket 的世界变换
    └─ TargetLocationWorldSpace / TargetRotationWorldSpace
                         │
动画工作线程执行 RefreshFeet()
    ├─ 处理传送
    ├─ 处理移动基座切换
    └─ RefreshFootLock()
          ├─ 更新 LockAmount
          ├─ 捕获或保持 Lock Transform
          ├─ 转换世界空间、移动基座空间和组件空间
          ├─ 限制腿部扭转与脚部旋转
          └─ Target 与 Lock 按 LockAmount 混合
                         │
FinalLocation / FinalRotation（Skeletal Mesh 组件空间）
                         │
GetControlRigInput() → AB_Als → CR_Als
                         │
                 脚部 IK 与 Foot Offset
```

左脚和右脚使用同一套流程，只是读取的曲线和 `FAlsFootState` 不同。

## 动画曲线分别控制什么

| 曲线 | 职责 |
| --- | --- |
| `FootLeftIk` / `FootRightIk` | 控制对应脚的 IK 是否有效，也是 Foot Lock 的总开关之一 |
| `FootLeftLock` / `FootRightLock` | 描述脚掌支撑阶段，决定锁定量以及何时捕获、保持和释放锁点 |
| `FootPlanted` | 描述停止阶段哪只脚已经或将要落地，主要服务于停止和过渡判断 |
| `FeetCrossing` | 描述双腿交叉程度，供脚部解算避免不合适的修正 |

`RefreshFeet()` 会把左右脚的 IK 曲线和 Lock 曲线都限制到 `0 ~ 1`。Foot Lock 是否真正有效取决于二者的乘积：

```text
EffectiveFootLock = IkAmount × LockAmount
```

因此只把 `FootLeftLock` 写成 `1` 并不够。如果同一时刻 `FootLeftIk` 为 `0`，锁定状态仍会被清除，最终脚变换直接退回动画提供的目标变换。

Epic 的动画曲线本质上是随 Animation Sequence 时间轴变化的浮点值。把 IK 和锁定时机写进曲线，可以让脚部接触阶段跟随动画本身，而不是根据速度或计时器猜测脚何时落地。

## 锁定量为什么只允许直接锁满

`RefreshFootLock()` 对 Lock 曲线采用非对称更新规则：

- 新值达到满权重时，可以捕获新锁点，并把内部 `LockAmount` 设置为 `1`。
- 新值小于或等于上一帧时，可以正常下降，用于逐渐释放锁定。
- 新值只是从 `0` 上升到 `0.2`、`0.5`、`0.8` 时，不会逐帧增加内部锁定量。

也就是说，曲线上升段不是“边移动边渐渐锁住”。脚必须先进入明确的完整支撑帧，系统才会保存锚点；之后曲线下降时，脚再从锁点平滑过渡回动画目标。

这样设计可以避免脚还在摆动时就捕获一个不稳定的位置。如果允许部分权重持续上升，锁点和动画目标会在脚尚未落稳时互相拉扯，容易出现减速、漂移或突然吸附。制作曲线时应确保支撑阶段真正达到满权重，而不是只接近 `1`。

当锁定量已经接近满权重后，代码还会尽量沿用原有锁点，避免动画混合造成曲线短暂下降后再次回到 `1` 时，脚突然重新捕获到另一个位置。

## 锁点从哪里捕获

游戏线程的 `RefreshFeetOnGameThread()` 每帧读取左右脚目标 Socket 的世界变换：

- 开启 `bUseFootIkBones` 时读取 `ik_foot_l` 和 `ik_foot_r`。
- 关闭时读取 `VB foot_l` 和 `VB foot_r` 虚拟骨骼。

这些值写入 `TargetLocationWorldSpace` 和 `TargetRotationWorldSpace`，表示当前动画姿势希望脚位于哪里。

Lock 曲线首次达到满权重时，正常情况下不会直接捕获本帧的 `Target`，而是使用上一帧保存的 `FinalLocation` 和 `FinalRotation`，将它们从组件空间重新转换到世界空间。这里保存的是上一帧已经显示出来、但尚未叠加地面贴合偏移的脚部目标，可以避免曲线刚变成 `1` 时脚突然跳到本帧动画已经推进后的新位置。

如果脚部状态刚刚恢复有效，没有可信的上一帧结果，才会直接使用当前 `TargetLocationWorldSpace` 和 `TargetRotationWorldSpace` 初始化锁点。

## 为什么锁住世界坐标就不滑了

Foot Lock 防滑的本质**不是给脚加一个反向力或反向速度**，而是把 IK 目标从“跟着身体一起动的动画脚位置”换成“钉死在世界坐标里的一个固定点”。

假设角色以每帧 5 cm 向前移动，左脚在 t=0 落地进入支撑阶段。不锁脚时，`ik_foot_l` 挂在胶囊上，每帧跟着身体走 5 cm，脚在地面上滑：

| 帧 | 身体位置 | 动画脚目标（世界） | 结果 |
| --- | --- | --- | --- |
| t=0 | x=0 | x=0 | 落地 |
| t=1 | x=5 | x=5 | 脚跟着身体滑 5 cm |
| t=2 | x=10 | x=10 | 又滑 5 cm |

锁脚后，`RefreshFootLock()` 在 t=0 捕获一个固定世界锚点，之后每帧在“动画目标”和“锁点”之间做 `Lerp`：

```cpp
FinalLocation = Lerp(TargetLocationWorldSpace, LockLocationWorldSpace, LockAmount);
```

支撑阶段 `LockAmount = 1`，最终目标**完全等于锁点**，动画目标被彻底忽略：

| 帧 | 身体位置 | 动画目标（世界） | 锁点（世界） | Final（世界） | 结果 |
| --- | --- | --- | --- | --- | --- |
| t=0 | x=0 | x=0 | 捕获 x=0 | x=0 | 落地 |
| t=1 | x=5 | x=5 | x=0 | x=0 | 脚留在原地 |
| t=2 | x=10 | x=10 | x=0 | x=0 | 脚仍留在原地 |

锁点是常数，所以 IK 每帧都把脚骨解算到这个固定点，脚就钉在地上了。身体继续从脚上方移过去，腿被拉长或转动去够这个锚点——这就是“脚不滑”。

注意 `LockAmount` 表达的是“脚该被钉住多少”，它在“动画目标”和“锁点”之间插值，而不是“给脚施加多大的水平反向位移”。真正让脚静止的，是“目标本身是世界里的一个固定点”这个事实。

## 多个空间字段只是同一个锚点的不同表示

上面说的“固定世界锚点”是核心。`FAlsFootState` 里的多个字段不是多套机制，只是把**同一个锁点**在不同坐标系里各存一份，方便不同环节读取：

| 字段 | 空间与用途 |
| --- | --- |
| `TargetLocationWorldSpace` / `TargetRotationWorldSpace` | 当前动画生成的脚部目标，世界空间 |
| `LockLocationWorldSpace` / `LockRotationWorldSpace` | 当前锁定锚点，世界空间（最直观的核心表示） |
| `LockLocationMovementBaseSpace` / `LockRotationMovementBaseSpace` | 锁点相对移动基座的变换，移动平台用 |
| `LockLocation` / `LockRotation` | 锁点换算到 Skeletal Mesh 组件空间，供约束计算 |
| `FinalLocation` / `FinalRotation` | 目标与锁点混合后的组件空间结果，交给 Control Rig |

### 组件空间只是给 IK 换了个坐标系

Control Rig 在组件空间解算，所以固定世界锚点必须换算成组件空间：

```text
LockLocation(组件空间) = 组件变换⁻¹ × LockLocation(世界空间)
```

这不是第二个防滑机制，只是把同一个固定点翻译成 IK 能读的语言。身体往前走 5 cm 后，那个固定世界点在新的组件系里，就自动变成“相对身体往后 5 cm”：

- 世界视角：锁点没动，身体动了。
- 组件视角：身体没动，锁点相对身体往后退了。

两句话描述的是同一件事。IK 拿到“越来越靠后的组件空间目标”，就把腿往后够，视觉上脚留在原地。这里没有显式地给脚算一个反向位移——固定世界锚点在移动的组件系里，天然就表现为反向。

角色旋转同理：组件逆旋转会同时修正锁点的位置和朝向，所以原地转身时不需要手工按 Actor Yaw 算脚的反向旋转。这里的“组件空间”是 Skeletal Mesh 的组件坐标系；进入 Control Rig 后对应 Rig 的全局解算空间，不是 Unreal 世界空间。

## 移动平台上的锁定

如果角色站在具有相对位置的 Movement Base 上，脚不应该绝对固定在世界里，否则平台向前移动时脚会留在平台后方。系统会在捕获锁点时保存它相对于基座的变换：

```text
LockLocationBase = BaseRotation⁻¹ × (LockLocationWorld - BaseLocation)
LockRotationBase = BaseRotation⁻¹ × LockRotationWorld
```

后续每帧再根据基座当前变换重建世界锁点：

```text
LockLocationWorld = BaseLocation + BaseRotation × LockLocationBase
LockRotationWorld = BaseRotation × LockRotationBase
```

因此普通地面上的脚相对世界保持稳定，移动平台上的脚则相对平台保持稳定。平台的平移和旋转都会自然进入补偿链路。

当 Movement Base 或其 Bone 发生切换时，`ProcessFootLockBaseChange()` 会保留当前世界锁点，再把它重新表达为新基座空间的坐标。脚部数据刚恢复有效时则使用当前脚目标重新初始化，避免把过期锁点带到新的支撑面。

## 移动、离地和传送时如何退出或重建

### 开始移动或进入空中

即使动画曲线仍然保持锁定，代码也会主动降低 Lock Amount：

- `bMovingSmooth` 为真时以每秒 `5` 的速度释放。
- 不处于 Grounded 时以每秒 `0.6` 的速度释放。
- 脚部状态刚恢复有效且又满足上述条件时直接清零。

`bMovingSmooth` 在“同时具有输入和速度”或速度超过 `MovingSmoothSpeedThreshold` 时成立。这个保护避免动画曲线缺失、混合滞后或空中动画带有残留曲线时，脚仍被旧锁点拉住。

当 `bAllowFootLock` 关闭，或者 `IkAmount × NewLockAmount` 已不再具有有效权重时，世界空间、基座空间和组件空间的锁定缓存都会清空，`FinalLocation` 与 `FinalRotation` 直接使用当前动画目标。

### 传送

传送后如果仍把脚留在旧世界位置，腿会瞬间被拉向远处。`MarkTeleported()` 记录传送时间，`ProcessFootLockTeleport()` 在之后约 `0.2 s` 内把已有组件空间锁点重新投影到角色当前世界变换，并同步移动基座空间数据。

这里没有简单地立即关闭锁定。网络平滑可能让一次传送在视觉上分布到数帧，短时间持续重建锚点能让脚跟随角色完成这段修正，避免在旧位置和新位置之间抽动。

### 长时间未更新

如果 Mesh 没有持续 Tick，`MarkPendingUpdate()` 会让脚部状态失效。恢复更新后，系统先验证 Pelvis Socket 变换，再把 `bBecameValid` 标记为真，并在需要锁定时以当前脚目标重新初始化。这样不会继续使用暂停前的过期锁点。

## 腿部和脚部旋转约束

完全固定世界锁点并不总是符合人体结构。角色快速旋转时，锁点可能跑到大腿轴线侧后方，使腿部 IK 扭成螺旋。因此 `ConstrainFootLock()` 做两层限制。

第一层是大腿方向限制。它将骨盆组件空间旋转应用到左右腿各自的 `ThighAxisPelvisSpace`，再计算该轴线与脚部锁定位置在 XY 平面上的夹角。超过 `ThighAngleLimit` 时，锁点的位置和旋转会绕组件 Up 轴回转到允许范围。默认限制为 `90°`。

第二层是脚部朝向限制。代码计算锁定旋转相对当前动画目标旋转的世界空间 Up 轴 Twist，只保留 `FootAngleLimit` 范围内的偏差。默认限制为 `40°`。这可以防止脚掌为了坚持旧朝向而相对腿部旋转过大。

这两个参数不是锁定强度。它们定义的是“为了保持自然腿型，最多允许锁点偏离当前身体姿势多少”。限制过大容易出现膝盖翻转和脚掌扭曲；限制过小则会更早牺牲锁定效果，表现为原地转身时脚缓慢挪动。

## 最终结果如何进入动画图

约束完成后，代码在世界空间混合动画目标和锁定目标：

```text
FinalLocationWorld = Lerp(TargetLocationWorld, LockLocationWorld, LockAmount)
FinalRotationWorld = Normalize(FastLerp(TargetRotationWorld, LockRotationWorld, LockAmount))
```

结果随后转换为 Skeletal Mesh 组件空间，保存到 `FinalLocation` 和 `FinalRotation`。

`GetControlRigInput()` 将左右脚的最终组件空间变换，以及 `bFootTransformsValid` 等状态打包为 `FAlsControlRigInput`。主动画蓝图 `AB_Als` 通过线程安全的属性访问调用该函数，并把 `RigInput` 传给 Control Rig 资产 `CR_Als`；Monolithic 版本使用同样的数据出口。

`CR_Als` 内部读取左右脚位置、旋转和脚部曲线，使用腿部 IK 将脚骨解算到目标变换。同一个 Rig 还包含 `Foot Offset Trace`、位置偏移和旋转偏移节点，用于后续地面贴合。最终画面中的脚部姿势因此是动画原始姿势、Foot Lock 目标、地面偏移和腿部 IK 约束共同作用的结果。

`bFootTransformsValid` 很重要：如果游戏线程还没有得到可信的骨骼变换，Control Rig 不应消费零值或旧值，否则脚可能瞬间跳到组件原点。

## Foot Lock 与 Foot Offset 的区别

| 对比项 | Foot Lock | Foot Offset / 地面贴合 |
| --- | --- | --- |
| 解决的问题 | 支撑脚随角色根骨或动画混合滑动 | 脚悬空、穿地或不贴合坡面 |
| 主要输入 | 动画目标变换、Lock/IK 曲线、角色与移动基座变换 | 脚下射线检测、命中位置、地面法线 |
| 主要修正 | 保持脚的位置和朝向锚点 | 调整脚的高度和坡面旋转 |
| 是否检测地面 | 否 | 是 |
| 平地是否有价值 | 有，可减少停止和转身脚滑 | 通常偏移接近零 |

Foot Lock 不能保证锁点就在真实地面上，它只保持捕获时的脚部目标。Foot Offset 也不能代替锁定：即使每帧都正确贴地，脚仍可能沿地面水平滑动。两者应当串联使用，但调试时必须分开观察。

## 与 Dynamic Transition 的关系

锁点长期保持后，动画期望位置和锁点之间可能逐渐产生较大距离。`RefreshDynamicTransitions()` 会比较 `TargetLocationWorldSpace` 与 `LockLocationWorldSpace` 的距离；超过阈值时，选择对应脚的 Additive Transition 动画，让角色主动挪脚并建立更合理的新支撑姿势。

因此 Foot Lock 负责短时间稳定接触，Dynamic Transition 负责在误差过大时通过可见的迈步动作释放结构压力。只锁不挪会让腿越扭越不自然，只播放过渡而没有锁定则仍会看到细小脚滑。

## 常见故障

### Lock 曲线有值但脚没有锁住

同时检查对应的 `FootLeftIk` 或 `FootRightIk`。IK 曲线为零、`bAllowFootLock` 关闭、脚部变换无效，都会让锁定立即失效。还要确认 Lock 曲线确实达到满权重；只上升到 `0.9` 左右不会触发新的完整锁点捕获。

### 脚在锁定瞬间跳一下

优先检查 Lock 曲线达到 `1` 的时间是否与脚掌真正落稳一致，以及动画混合是否让不同序列的脚部曲线不同步。还应确认 `FinalLocation` 没有因为 Mesh 停止更新而过期，脚部 IK 骨或虚拟骨的骨架映射也必须正确。

### 角色向前移动时脚仍跟着身体滑

观察 `LockLocationWorldSpace` 是否保持稳定，再观察 `LockLocation` 是否随当前 Component Transform 反向变化。如果世界锁点本身也跟着角色移动，通常是锁点被反复捕获、传送状态持续触发，或角色被错误识别为站在移动基座上。

### 原地旋转时膝盖翻转或腿扭成螺旋

检查 Pelvis Socket 组件空间旋转、左右腿的 `ThighAxisPelvisSpace` 方向，以及 `ThighAngleLimit`。若限制逻辑正常但仍翻转，还要检查 Control Rig 中 Two Bone IK 的 Pole Vector 与骨骼初始轴向。

### 移动平台上脚留在空中

检查 Character 的 Based Movement 是否正确设置、`HasRelativeLocation()` 是否成立，以及基座组件和 Bone 是否频繁变化。Foot Lock 只有拿到稳定的 Movement Base，才能保存并重建基座空间锁点。

### 传送后腿被拉长

确认所有传送路径都会调用 `MarkTeleported()`，或能被单帧距离阈值检测到。网络模拟代理还需要关注复制位置和 Based Movement 更新是否正确触发传送标记。

### 脚锁住了，但仍然穿地或不贴坡

这是 Foot Offset 链路的问题。检查 `Foot Offset Trace` 的碰撞通道、上下检测距离、可行走坡度和 Foot Height，而不是继续调 Lock Amount。

## 推荐调试顺序

1. 在动画序列中确认左右脚的 IK 和 Lock 曲线值及时间点。
2. 观察 `TargetLocationWorldSpace`，确认脚部 Socket 来自动画期望位置。
3. 观察 `LockAmount` 是否只在曲线满权重时建立，并在移动或离地时下降。
4. 在普通地面上检查 `LockLocationWorldSpace` 是否稳定。
5. 移动或旋转角色，检查组件空间 `LockLocation` 是否产生反向补偿。
6. 在移动平台上检查 `LockLocationMovementBaseSpace` 是否稳定，而世界锁点是否跟随平台。
7. 最后检查 `FinalLocation`、`FinalRotation` 是否经 `GetControlRigInput()` 到达 `CR_Als`，再单独调试 Foot Offset Trace 与腿部 IK。
