# 04.3 移动方向与 Rotation Yaw Offset

> Grounded 动画既要知道角色“正在往哪里移动”，也要知道身体相对视角应当保留多少偏转。前者用于选择方向状态，后者通过曲线驱动动画中的旋转偏移。

## 这篇笔记解决什么问题

移动方向不是输入方向，也不是角色当前朝向，而是“实际速度相对于视角方向的结果”。ALS 在 Grounded 更新中先把世界空间速度方向转换到视角空间，再分别生成两类数据：

- `MovementDirection`：离散的方向缓存，例如 Forward、Backward、Left、Right，用于选择或混合对应方向的移动动画。
- `RotationYawOffsets`：连续的四组旋转偏移角度，用于让动画姿势根据移动方向产生自然的身体扭转。

这两个数据的输入相同，但职责不同。前者回答“当前属于哪个方向”，后者回答“该方向下动画应该偏转多少”。它们也不同于 [Velocity Blend](./04.2-局部速度与VelocityBlend.md)：Velocity Blend 保存的是连续的方向权重，而不是一个离散方向标签。

## 数据流

```text
世界空间速度方向
        │
        ├─ 减去视角 Yaw，得到相对视角的速度角度
        │
        ├─ MovementDirection
        │      └─ 角度分区 → Forward / Backward / Left / Right …
        │
        └─ RotationYawOffsets
               └─ 四条方向曲线 → Forward / Backward / Left / Right 偏移角度
```

在 `RefreshGroundedMovement()` 中，核心计算可以概括为：

```text
VelocityYawAngleViewSpace
    = UnwindDegrees(VelocityYawAngleWorldSpace - ViewYaw)
```

`UnwindDegrees()` 将角度收敛到常用的 `-180° ~ 180°` 范围，避免角度从 `359°` 跳到 `0°` 时产生不连续的判断。

## MovementDirection 如何计算

`RefreshMovementDirection()` 使用相对视角的速度角度调用 `CalculateMovementDirection()`。当前实现使用：

- 前方半角：`70°`
- 方向切换阈值：`5°`

如果暂时不考虑 `5°`，`70°` 可以理解为前方扇区的半角：速度方向处于 `-70° ~ 70°` 时属于 Forward。右侧区间从 `70°` 开始，左侧区间从 `-70°` 开始；接近正负 `180°` 的区域属于 Backward。

`AngleThreshold` 会把各方向的判定范围向外扩展 `5°`。代入源码后，各条件实际是：

| 判断顺序 | 条件范围 | 返回方向 |
| --- | --- | --- |
| 1 | `-75° ~ 75°` | Forward |
| 2 | `65° ~ 115°` | Right |
| 3 | `-115° ~ -65°` | Left |
| 4 | 其余角度 | Backward |

这些条件存在重叠，例如 `65° ~ 75°` 同时满足 Forward 和 Right。函数按 Forward、Right、Left、Backward 的顺序依次判断，所以第一个命中的方向优先。最终有效分区可以近似理解为：

```text
-180       -115       -75          0          75        115        180
  └ Backward ┴── Left ──┴────── Forward ──────┴─ Right ──┴ Backward ┘
```

以从前方向右转为例：

- `60°`：属于 Forward；
- `70°`：Forward 和 Right 的条件都满足，但 Forward 先判断，因此仍然是 Forward；
- `74°`：仍然是 Forward；
- `76°`：已经超出 Forward 范围，切换为 Right；
- `116°`：超出 Right 范围，切换为 Backward。

因此，`5°` 的直接效果是给方向区间增加容差，使角色不会一越过名义上的 `70°` 就立刻从 Forward 切到侧向，而是要继续转到 `75°` 之外。这样可以减少角度在原始分界线附近的小幅噪声造成的过早切换。

不过，这里要和真正的“滞回”区分开。当前函数没有读取上一帧的方向，从 Forward 进入 Right 和从 Right 返回 Forward 使用的是同一条有效边界 `75°`。如果角度在 `74.8°` 与 `75.2°` 之间持续波动，方向仍可能来回变化。真正的滞回通常会根据当前方向使用不同的进入和退出阈值，例如超过 `75°` 才进入 Right，但必须回到 `65°` 以内才返回 Forward。

所以这里更准确的说法是：`AngleThreshold` 扩大了方向判定范围，并通过重叠区间与判断顺序为 Forward、Left、Right 提供边界容差；它能减少原始边界附近的误切换，但不能彻底消除新边界处的抖动。

需要注意，方向的来源是速度而不是输入：

- 输入方向表示玩家希望角色往哪里走；
- 速度方向表示角色此刻实际上往哪里走；
- 角色朝向表示模型或控制器当前面向哪里。

例如角色受到外力、处于加速过程、在斜坡上滑动，或者移动组件还没有来得及达到目标速度时，输入方向和实际速度方向可能不同。动画应优先反映实际运动，否则脚步方向会与位移不一致。

## VelocityDirection 与 Sprint 为什么强制 Forward

当旋转模式为 `VelocityDirection` 时，角色通常会持续把自身朝向对齐到速度方向。此时从视角看，侧向或后向移动并不是主要表现，动画系统将 `MovementDirection` 固定为 Forward，避免由于视角变化而切换到不符合角色姿态的侧向循环。

冲刺时也固定为 Forward。冲刺动画通常是专门制作的向前跑动周期，身体、手臂和步幅都围绕前向运动设计。如果允许冲刺状态进入侧向或后向方向分支，就可能出现速度仍然很高，但动画却使用不匹配的方向循环。

这并不意味着速度方向在这两种情况下被修改了。被固定的是动画选择用的离散缓存，实际速度、局部速度和旋转偏移仍然可以继续参与其他动画计算。

## RotationYawOffsets 的作用

`RefreshRotationYawOffsets()` 使用相对视角速度角度，分别查询四条曲线：

```text
ForwardCurve(angle)  → ForwardAngle
BackwardCurve(angle) → BackwardAngle
LeftCurve(angle)     → LeftAngle
RightCurve(angle)    → RightAngle
```

曲线把“移动方向角度”映射成“动画旋转偏移角度”。例如向右移动时，可以让骨盆、躯干或脚步方向向右产生一定偏转；向后移动时，则使用另一条曲线控制身体回收或扭转的幅度。曲线不是简单的固定角度，而是允许在不同角度区间内使用不同的姿态修正。

这些值写入 `GroundedState.RotationYawOffsets`，随后由动画图中的 Rotation Yaw Offset 相关节点读取。它主要改变动画姿势的表现，不等同于角色移动组件或角色旋转逻辑：

- 角色旋转逻辑决定 Actor 的实际朝向；
- `RotationYawOffsets` 决定动画姿势相对基础朝向如何偏转；
- 两者叠加后，玩家看到的是既符合移动方向、又保留转身惯性的身体表现。

## 与 Velocity Blend 的区别

以角色相对视角向右前方移动为例：

- `VelocityBlend` 会产生 Forward 和 Right 两个连续权重，用于混合前进与侧向姿势；
- `MovementDirection` 会选择一个离散方向类别，供方向状态或循环选择使用；
- `RotationYawOffsets` 会根据速度角度查询四条曲线，生成身体旋转偏移。

三者可以同时存在，但不能互相替代。Velocity Blend 解决“各方向姿势混合多少”，Movement Direction 解决“当前属于哪类方向”，Rotation Yaw Offset 解决“动画姿势应如何偏转”。

## 调试时如何定位问题

### 角色移动方向与动画方向不一致

先检查传入的 `VelocityYawAngleWorldSpace` 是否来自实际速度，再检查减去的是否是当前视角 Yaw。若误用了输入角度或 Actor Yaw，常见结果是输入改变后动画立即转向，但角色实际位移仍滞后。

### 方向在边界处闪烁

检查角度是否做了 `UnwindDegrees()`，以及方向计算的边界阈值是否过小。还应确认速度接近零时没有用一个不稳定的角度参与分类；停止阶段应由停止/起步逻辑接管，而不是继续依赖一个几乎没有意义的速度方向。

### Rotation Yaw Offset 方向反了

检查曲线输入的正负方向与项目坐标约定，尤其是 Left/Right 曲线是否把 Yaw 正负写反。再确认动画图是否将偏移应用在预期的骨骼层级上；代码中的角度值正确，并不代表最终姿势一定正确。

### 曲线有值但画面没有效果

检查 `GroundedState.RotationYawOffsets` 是否确实被动画图读取，以及曲线资产是否绑定到了 `GroundedSettings` 的对应字段。还要区分“代码状态有值”和“动画图节点实际使用了该值”这两个环节。
