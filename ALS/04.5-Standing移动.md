# 04.5 Standing 移动

> Standing 移动状态把速度、步态、步幅和冲刺阶段整理成动画图可直接使用的参数，同时为 Pivot 提供低速激活条件。

## 这篇笔记解决什么问题

Standing 状态并不是简单地在 Walk、Run、Sprint 三个动画之间切换。它还需要解决三个连续性问题：

1. 角色实际速度和动画制作速度不一致时，脚步不能明显滑动；
2. Walk 与 Run 的姿势可以混合，但步幅调整不能被同一套混合逻辑绑死；
3. 冲刺起步和 Pivot 需要额外的短时状态数据，不能污染普通移动循环。

`FAlsStandingState` 保存的正是这些供动画图消费的结果：`StrideBlendAmount`、`WalkRunBlendAmount`、`PlayRate`、`SprintBlockAmount`、`SprintTime`、`SprintAccelerationAmount` 和 `bPivotActive`。

## Standing 更新流程

```text
LocomotionState.Speed / CapsuleScale
             │
             ├─ StrideBlendAmount
             │      └─ Walk 曲线与 Run 曲线按步态混合
             │
             ├─ WalkRunBlendAmount
             │      └─ Walking = 0，其他站立步态 = 1
             │
             ├─ PlayRate
             │      └─ 速度 ÷ 动画标定速度 ÷ StrideBlend
             │
             ├─ SprintBlockAmount
             │      └─ 读取动画曲线
             │
             └─ SprintTime / SprintAccelerationAmount
                    └─ 仅在冲刺开始阶段保留加速表现
```

初始化时，`SprintTime` 归零，`bPivotActive` 关闭。之后 `RefreshStandingMovement()` 每次根据当前运动状态刷新数据。

## StandingState 各字段职责

| 字段 | 作用 |
| --- | --- |
| `StrideBlendAmount` | 调整动画步幅，让脚步周期适应当前速度 |
| `WalkRunBlendAmount` | 在 Walk 与 Run 类姿势之间选择或混合 |
| `PlayRate` | 调整移动循环播放速度 |
| `SprintBlockAmount` | 控制冲刺被阻挡或受限时的动画表现 |
| `SprintTime` | 记录本次冲刺开始后经过的时间 |
| `SprintAccelerationAmount` | 提供冲刺起步阶段的前向加速姿势 |
| `bPivotActive` | 表示当前速度是否满足 Pivot 动画的准备条件 |

这些字段不是互相替代的。尤其是 `StrideBlendAmount` 和 `WalkRunBlendAmount`：前者调整脚步幅度，后者调整步态姿势。

## Stride Blend 不是 Walk/Run 混合

ALS 为 Walk 和 Run 分别配置“速度 → 步幅”的曲线：

```text
WalkStride = WalkCurve(Speed)
RunStride  = RunCurve(Speed)
StrideBlend = Lerp(WalkStride, RunStride, UnweightedGaitRunningAmount)
```

`PoseState.UnweightedGaitRunningAmount` 描述当前姿势中运行步态的比例。这样可以让动画姿势按照步态独立混合，同时让步幅根据速度连续调整。

如果把所有工作都交给一个 Walk/Run Blend Space，常见结果是：角色速度处于两者之间时，系统播放“半 Walk + 半 Run”，脚步周期和位移速度却未必匹配。Stride Blend 提供了另一条控制通道，让动画保持合适的脚步距离。

可以把两者理解为：

- `WalkRunBlendAmount`：我更像 Walk 还是 Run？
- `StrideBlendAmount`：在当前速度下，我的每一步应该跨多远？

## WalkRunBlendAmount 的当前实现

当前 C++ 实现是离散的：

```text
Gait == Walking  → 0
其他情况         → 1
```

因此它并不是一个完整的连续步态比例。连续的步态影响主要由 `UnweightedGaitRunningAmount` 参与 Stride Blend 和播放速度计算。阅读动画图时，不要看到字段名里有 Blend 就默认它一定来自连续插值。

## PlayRate 如何计算

Standing 的动画标定速度默认是：

- Walk：`150 cm/s`
- Run：`350 cm/s`
- Sprint：`600 cm/s`

系统先根据当前步态和 `UnweightedGaitRunningAmount`，在相邻步态的标定速度之间插值，得到基础速度比例。随后再除以步幅混合值：

```text
PlayRate = Clamp(BaseSpeedAmount / StrideBlendAmount, 极小值, 3.0)
```

这样，当步幅变小时，播放速率会相应提高；当步幅变大时，播放速率会降低。速度、步幅和脚步周期共同决定最终节奏。

代码特意不允许 `PlayRate` 精确为零。因为某些引擎版本中，播放速率为零可能导致 AnimNotify 持续被当作每帧触发，产生重复事件。最终值还会限制在 `0~3` 的合理范围内，避免错误配置让动画无限加速。

## Sprint Acceleration 为什么只持续 0.5 秒

进入 Sprint 后，系统开始累计 `SprintTime`。前 `0.5` 秒内，`SprintAccelerationAmount` 使用当前的前向加速度；超过阈值后将它清零：

```text
SprintTime < 0.5s  → 使用 GetAccelerationAmount().X
SprintTime >= 0.5s → 0
```

这个参数表达的是“冲刺起步的爆发感”，不是整个冲刺过程的持续倾斜。如果一直把加速度姿势保留到冲刺末尾，即使角色已经稳定匀速，动画仍会像刚刚开始冲刺，导致身体前倾过久。

非 Sprint 状态会同时重置 `SprintTime` 和 `SprintAccelerationAmount`，保证下一次冲刺从干净的起点开始。首次更新时，`bPendingUpdate` 会把 Sprint 时间视为已达到阈值，避免初始化帧错误地播放一次冲刺加速。

## SprintBlockAmount

`SprintBlockAmount` 每帧读取 `SprintBlock` 曲线并限制到 `0~1`。它通常不是用来判断角色能否冲刺的游戏逻辑，而是把动画曲线提供的阻挡程度传递给站立移动图，用于调整冲刺姿势、手臂动作或过渡表现。

因此需要区分：

- 能否进入 Sprint：由角色移动和步态逻辑决定；
- 已进入 Sprint 后如何表现受阻：由 `SprintBlockAmount` 参与动画表现。

## Pivot 激活条件

`ActivatePivot()` 的当前条件只有一个：

```text
bPivotActive = LocomotionState.Speed < PivotActivationSpeedThreshold
```

默认阈值是 `200 cm/s`。它表示角色速度已经足够低，可以准备使用 Pivot 相关动画。这个字段只是一个准备条件，不代表此刻已经播放 Pivot，也不负责决定 Pivot 的方向、动画序列或状态机转换。具体的起步、停止和转身流程应结合 [起步、停止与转身](./06-起步停止与转身.md) 一起阅读。

如果 Pivot 过早或过晚激活，先检查：

- 使用的是未缩放还是已缩放的速度；
- `PivotActivationSpeedThreshold` 是否与项目动画制作速度匹配；
- 后续状态机是否真的读取了 `bPivotActive`；
- 低速阶段是否存在速度抖动，导致激活条件反复变化。

## 常见问题

### 脚步滑动

优先检查三项：动画标定速度、Stride 曲线和 Play Rate。只调播放速率可能暂时掩盖问题，但如果步幅曲线不匹配，角色在不同速度区间仍会出现脚步接触点不稳定。

### Walk 和 Run 混合很突兀

确认 `WalkRunBlendAmount` 的输入和动画图的使用方式。当前实现只提供 Walk/非-Walk 的二值结果，连续过渡不能期待来自这个字段本身，还要检查姿势层中的 gait amount 曲线和混合设置。

### 冲刺加速姿势一直存在

检查 `SprintTime` 是否在退出 Sprint 时重置，以及动画图是否把 `SprintAccelerationAmount` 直接叠加而没有按时间或权重衰减。C++ 端超过 `0.5` 秒会清零，若画面仍保留，问题通常在动画图或缓存姿势。

### Pivot 没有播放

`bPivotActive` 只是激活条件。应继续检查状态机转换、Pivot 方向判断、动画资源和速度阈值，而不是只盯着这个布尔值。
