# Kai Locomotion：起步——靶向与非靶向的动画选择

> 起步动画由步态、输入方向、姿态和靶向模式共同决定；非靶向的大角度输入可以升级为带旋转的起步，而靶向始终按方向选择平移起步。

## 解决的问题

角色从静止进入移动时，速度尚未形成，不能用循环动画的速度方向决定第一步。尤其是非靶向状态下横向或后向输入可能需要角色先转身；靶向状态下身体应保持面向目标，横移和后退则应直接播放对应方向的起步。

## 工作方式

`SetupStandingStartState()` 取局部加速度方向，结合 `RotationDirection` 形成 `StartDir`，再归类出 `StartCardinalDir`。随后将卡迪纳尔方向、连续角度、`bIsStrafing`、蹲伏状态和步态传入 `SelectStartAnimation()`。

数据资产的站立选择顺序如下：

1. 先按 Walk / Run / Sprint 取得该步态的起步集。
2. 若为**非靶向**且该动作集启用 `HasRotatingStarts`：绝对方向角不大于 60° 时，仍从四向 `StrafeStarts` 选动作；大于 60° 时，按正负方向选择右/左 90° 或 180°旋转起步。
3. 靶向，或未配置旋转起步时，直接从四向 `StrafeStarts` 选择。

变量名 `StrafeStarts` 描述的是数据资产的四向槽位，不代表它只能用于靶向；非靶向的小角度起步同样会使用它。

### Sequence Evaluator 的起始相位

`Sequence Evaluator` 不像普通 `Sequence Player` 那样只能从 0 秒自然累积播放；Kai 可以为它设置显式时间，使起步动画直接落在与当前运动情况相符的相位。

初始化时会计算两个候选时间：

- `RotStartTime = GetTimeAtRotation(RotationAlpha)`：从旋转曲线找到当前旋转完成度对应的动画时间。
- `DistStartTime = GetTimeAtDistance(1)`：从距离曲线找到累计位移约为 `1` 时的动画时间。

这里需要区分首次进入和状态重设：`StandingAnimState` 已是 `EStart` 时，使用 `RotStartTime`；如果旋转曲线没有返回有效时间（`0`），则回退到 `DistStartTime`。从 Idle 等其他状态首次进入 Start 时，代码使用 `DistStartTime`。因此并不是无条件“旋转曲线优先”。

首次起步优先按距离定位，是为了让第一步先与刚产生的地面位移对齐；起步状态重设时优先恢复旋转进度，则可避免角色在转身过程中跳回动作开头。

### 距离匹配如何推进第一步

进入状态后，`UpdateStandingStartState()` 将本帧实际位移 `FrameDisplacement` 交给 `AdvanceTimeByDistanceMatching()`。它的目标不是固定速率播放动画，而是使动画距离曲线代表的位移追随角色真实走过的距离：角色实际位移更大时，Evaluator 可推进得更快；位移更小时，则放慢推进。

起步初段的距离曲线值小于 `2` 时，Kai 临时将播放速率上限放宽到 `2.0`，再把最终钳制范围从较宽的 `[0.5, 1.5]` 逐步插值回动作集配置的 `PlayRateClamp`。这样刚进入状态时更容易追上正确的第一步相位，之后再回到稳定的播放速率限制。

### FirstStepAlpha 与 Warping 的放开时机

`FirstStepAlpha` 将当前动画时间从 `[0.1, 0.4]` 映射到 `[0, 1]`：第一步尚未建立时为 0，约 0.4 秒后为 1。

- `StrideWarpingAlpha` 始终随 `FirstStepAlpha` 逐渐放开。
- 非旋转起步的 `OrientationWarpingAlpha` 同样逐渐放开。
- 旋转起步初始化时将 `OrientationWarpingAlpha` 设为 0，优先由动作自身的旋转处理身体方向。

这样可以先保留原始起步动作的落脚和重心，等第一步基本稳定后再允许 Warping 吸收速度、方向偏差，减少脚滑和腿部拉扯。

### 旋转型起步如何驱动角色 Yaw

带旋转的起步每帧从旋转曲线读取当前进度，并映射为本次动作从起始相位到结束的旋转完成度。`RotationMatching()` 会在动画目标转角之外，叠加起步后当前加速度方向相对入状态方向的变化，写出新的 `CustomRotationYaw`。

完整链路是：

```text
起步动画 Rotation Curve
→ RotationMatching
→ CustomRotationYaw
→ UKLSCharacterMovementComponent::PhysicsRotation
→ Actor / Capsule 实际转向
```

旋转型起步会将旋转模式设为 `EAnimRot`。移动组件仍要求 `KLSCustomRotation` 曲线权重满足条件且没有 Root Motion Source，才会在 `PhysicsRotation()` 中实际采用 `CustomRotationYaw`；因此 Rotation Matching 不会绕过角色移动组件直接修改角色朝向。

## 实现要点

- 起步资源的最小维度是：站立/蹲伏、步态（站立）、四向平移起步，以及可选的左右 90°/180°旋转起步。
- 非靶向旋转起步会将 `CustomRotationType` 设为 `EAnimRot`；非旋转的前向起步使用 `EInterpolate`，其余情况保持 `EHold`。这是角色旋转与动作阶段一致的关键。
- 起步可提前过渡到 Loop：非旋转起步的第一步完成后，若旋转偏差达到 50°或速度方向已改变，会请求切出；步态改变、距离匹配所需播放速率超出钳制范围、或动画接近结尾也会触发。
- 蹲伏走相同的靶向/非靶向选择规则，但不按 Walk / Run / Sprint 分组，使用 `CrouchAnimSet.Starts`。

## 常见问题

- **只导入四向起步，却开启 `HasRotatingStarts`。** 非靶向且输入角超过 60°时会请求旋转起步资源；数据资产必须完整配置或关闭该开关。
- **把 Rotation Matching 当成替代距离匹配。** 起步在每帧仍按位移推进动作；旋转匹配只负责旋转型起步的角色朝向。
- **忽略从起步到 Loop 的提前切出。** 该切出防止起步方向已失效时仍强行播完，状态图的过渡条件需保留对应标记。
