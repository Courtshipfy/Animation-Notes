# Kai Locomotion：起步——靶向与非靶向的动画选择

> 起步要连续回答三个问题：选哪段动画、从哪一帧开始播、每帧怎么推进。前两个在 Setup 时一次决定，第三个在 Update 里每帧做；贯穿始终的前提是——起步动画由距离匹配驱动，不是按时间自由播放。

## 解决的问题

角色从静止进入移动时，速度尚未形成，不能用循环动画的速度方向来决定第一步。非靶向下，横向或后向输入可能意味着角色要先转身再迈步；靶向下，身体应保持面向目标，横移和后退应直接播放对应方向的起步。

因此起步被拆成三件事：选一段合适的起步动画，从正确的相位开始播，然后每帧按真实位移推进它。

## 全貌：一个前提，三步走

理解起步，先记住一个前提：**起步动画由距离匹配驱动**——进入 Start 后，动画不是按时间自由播放，而是每帧被推到「动画根位移增量 = 胶囊体真实位移」的位置；胶囊不动，动画就停。Setup 里的 `SetExplicitTime()` 只设一次起始帧，之后不再按时间播。

在这个前提下，起步分三步：

1. **选资源**（Setup）：按步态、输入方向、靶向、蹲伏选出一段起步动画。
2. **定相位**（Setup）：在选定的动画里挑一个起始帧。
3. **逐帧推进**（Update）：距离匹配推时间，旋转匹配写朝向，Warping 逐步放开。

贯穿全程的是两条曲线的分工：**距离曲线管时间、旋转曲线管朝向**，二者通过「当前动画时间」耦合——动画时间由距离匹配决定，旋转曲线值又是这个时间的函数，所以「转到目标角度用多久」最终由距离匹配决定，旋转匹配只负责把曲线值换算成朝向。

## 工作方式

### 第一步：选资源

`SetupStandingStartState()` 先把输入规整成两个量：

- `StartDir`：局部加速度方向（相对角色正前方），再乘以 `RotationDirection` 得到带正负号的角度；符号决定旋转起步向右还是向左。
- `StartCardinalDir`：把 `StartDir` 按 10° 死区归类为前/后/左/右。

随后把这两个量连同 `bIsStrafing`、蹲伏状态、步态交给 `SelectStartAnimation()`。站立数据资产的选择顺序：

1. 按 Walk / Run / Sprint 取该步态的起步集 `GaitStarts`。
2. 若为**非靶向**且该起步集启用 `HasRotatingStarts`：`Abs(Direction) ≤ 60°` 时从四向 `StrafeStarts` 选；大于 60° 时按方向正负选右/左旋转起步，`Abs ≥ 120°` 选 180°，否则选 90°。
3. 靶向，或未配置旋转起步时，直接从四向 `StrafeStarts` 选。

蹲伏走同一套靶向/非靶向规则，但使用 `CrouchAnimSet.Starts`，不按步态分组。

`StrafeStarts` 是数据资产里四向槽位的名字，不代表它只用于靶向；非靶向的小角度起步同样用它。

### 第二步：定相位

`Sequence Evaluator` 与普通 `Sequence Player` 不同：后者只能从 0 秒自然累积播放，前者可以被 `SetExplicitTime()` 直接指定时间。因此起步动画的第一帧可以直接落在与运动情况相符的相位，而不是硬从 0 秒播。

这里先厘清两个都带「旋转」字样、但职责不同的量：

- `StartDir`（度，带正负）：本次输入相对角色正前方的角度，用来**选哪段起步动画**。非靶向下正好 60° 仍选平移起步，超过 60° 才选 90°/180° 旋转起步。
- `RotationAlpha`（0–1）：旋转完成度，用来**在已选动画里反查相位**。旋转曲线烘焙时把已完成的 Root Motion Yaw 除以该动画总 Yaw，归一化到 0–1。`SetupStandingStartState()` 只读取 `BaseAnimInstance->RotationAlpha`（动画蓝图层写入的值），并不在本函数内从摇杆角度计算它。

在选定的这一段动画里，Kai 计算两个候选起始时间：

- `RotStartTime = GetTimeAtRotation(RotationAlpha)`：旋转曲线反查「旋转完成到 `RotationAlpha`」对应的时间。
- `DistStartTime = GetTimeAtDistance(1)`：距离曲线反查「累计位移约为 1」对应的时间。距离曲线以 cm 为单位，`1` 只比开头多几帧，本质是「从动画开头起播」，不是「第一步落地」。

二者是同一段动画里的两个时间点，不是两段候选动画，也不会被混合。最终选择：

```text
若 RotStartTime == 0：RotStartTime = DistStartTime
AnimStartPosition = StandingAnimState 已是 EStart
    ? RotStartTime
    : DistStartTime
SetExplicitTime(AnimStartPosition)
```

含义是：

- 首次从 Idle 等其他状态进入 Start 时（`StandingAnimState` 还不是 `EStart`），直接取 `DistStartTime`。
- 若 Setup 执行前 `StandingAnimState` 已经是 `EStart`（起步已在播、又发生一次 Setup），优先取 `RotStartTime`。
- 旋转曲线反查不出非零时间（动画本身不旋转，或 `RotationAlpha` 为 0）时，回退到 `DistStartTime`。

为什么首次用 `DistStartTime`：起步动画由距离匹配驱动，起始时间只决定「动画根位移的 0 点」和「角色刚开始移动那一刻」如何对齐。`DistStartTime` 把这零点表达成「累计位移约 1 cm」，等价于「从动画开头起播」；用 `1` 而不是 `0`，效果是反查值落进曲线内部，而不是正好压在值为 0 的首个关键帧上（`GetTimeAtDistance(0)` 会直接命中 0）。首次起步因此从开头开始，让动画从根位移 0 起逐帧追上胶囊已经走过的距离；起步已在播时则优先用 `RotStartTime` 恢复已完成的旋转进度，避免转身跳回动作开头。

举一个例子：摇杆偏右前 60° 时，代码按输入角选平移起步，首次进入 Start 后从 `DistStartTime` 开始。输入 61° 且动作集启用旋转起步时，改选右转 90° 起步，首次仍从 `DistStartTime` 开始——并不会直接跳到「已转 61°」那一帧。只有 Start 已在播、再次 Setup 时，才可能用 `RotationAlpha` 反查到「例如已完成 40% 转身」的时间点，从那里继续。

### 第三步：逐帧推进

进入 Start 后，每帧由 `UpdateStandingStartState()` 推进。它把三件事串起来：距离匹配推时间、旋转匹配（旋转起步时）写朝向、Warping 按 `FirstStepAlpha` 逐步放开。

#### 距离匹配：决定时间

`UpdateStandingStartState()` 把本帧实际位移 `FrameDisplacement` 交给 `AdvanceTimeByDistanceMatching()`。它沿距离曲线向前走，走到「动画根位移增量 ≈ 这一帧真实位移」的位置，再把 `ExplicitTime` 设到那里。实际位移更大就推得更快，更小就放慢；`FrameDisplacement == 0` 时动画时间停住。

起步初段距离曲线值小于 `2` 时，Kai 临时把播放速率上限放宽到 `2.0`，再把最终钳制范围从较宽的 `[0.5, 1.5]` 逐步插值回动作集配置的 `PlayRateClamp`。这样刚进入状态时更容易追上正确的第一步相位，之后再回到稳定的播放速率限制。

#### 旋转匹配：决定朝向（用 75° 走一遍）

带旋转的起步每帧从旋转曲线读取当前进度，映射为本次动作从起始相位到结束的旋转完成度，再写出 `CustomRotationYaw`。

以非靶向、75° 摇杆输入为例：

1. `StartDir = +75°`，`Abs > 60°` 走旋转分支；`+75°` 为正 → 右，`Abs < 120°` → 选 **`Right_90`** 旋转起步。
2. Setup 记下 `TargetAngle = 75°`、`EntryAccelDir`、`EntryRotYaw`，`CustomRotationType = EAnimRot`，`OrientationWarpingAlpha = 0`。
3. 每帧先由距离匹配推动画时间，再从当前时间读旋转曲线：

```text
RotAlpha  = GetRotationCurveValue(当前动画时间)   // 0→1，这段 90° 转身完成了多少
MappedRot = 把 [StartRotAlpha, 1] 映射到 [0,1] 的 RotAlpha  // 起始相位≈开头，故 ≈ RotAlpha
AnimDesiredRotation = TargetAngle × MappedRot = 75° × MappedRot
CustomRotationYaw   = EntryRotYaw + AnimDesiredRotation + 加速度方向修正
```

`RotationMatching()` 在动画目标转角之外，还叠加「起步后加速度方向相对入状态方向的变化」（`AccelChange`，用 `RInterpTo` 按时间平滑），以应对起步过程中摇杆方向改变。

这里要分清节奏的归属：`RotAlpha` 是「当前动画时间」处的读数，而当前动画时间由距离匹配逐帧推进。所以「从正前转到 75° 用多久」由距离匹配决定（经动画时间 → 旋转曲线这条链）；`RotationMatching()` 只是把曲线值 × `TargetAngle` 换算成朝向写出去，它没有自己的时钟来控制转身节奏（仅加速度修正用了时间插值）。

最终朝向经 `CustomRotationYaw → PhysicsRotation → Actor/Capsule 实际转向` 落地。旋转型起步把旋转模式设为 `EAnimRot`；移动组件仍要求 `KLSCustomRotation` 曲线权重满足条件且没有 Root Motion Source，才会实际采用 `CustomRotationYaw`，因此 Rotation Matching 不会绕过移动组件直接改朝向。

注意朝向轨迹与转速的分工：动画层通过 `RotationMatching` 写出目标 yaw（轨迹），CMC 在 `PhysicsRotation()` 里用 `FixedTurn(当前Yaw, CustomRotationYaw, RotRate)` 执行，`RotRate = RotationRate × DeltaTime` 是每帧最多转多少度。所以正常时动画旋转曲线决定转速，CMC 只是执行；只有动画要求的转速超过 `RotationRate` 上限时，CMC 才成为限速者。非靶向 `EAnimRot` 模式下 `UpdateCustomRotation()` 对该值不做改写。

这里的要点是「90° 不是问题」：资源只是粗分档（`60~120°` 用 90° 模板、`>120°` 用 180° 模板、符号定左右），精确角度靠 `TargetAngle = 真实输入角` 乘在旋转曲线上，把模板转身等比缩放到实际角度。75° 输入不是「硬播一个 90° 转身」，而是「用 90° 转身的动作形状，把幅度拉到 75°」。

#### FirstStepAlpha 与 Warping 的放开时机

`FirstStepAlpha` 把动画时间从 `[0.1, 0.4]` 映射到 `[0, 1]`：第一步尚未建立时为 0，约 0.4 秒后为 1。

- `StrideWarpingAlpha` 始终随 `FirstStepAlpha` 逐渐放开。
- 非旋转起步的 `OrientationWarpingAlpha` 同样逐渐放开。
- 旋转起步初始化时把 `OrientationWarpingAlpha` 设为 0，由动作自身的旋转优先处理身体方向。

这样可以先保留原始起步的落脚和重心，等第一步基本稳定后再让 Warping 吸收速度、方向偏差，减少脚滑和腿部拉扯。

## 实现要点

- 起步资源的最小维度：站立/蹲伏、步态（站立）、四向平移起步，以及可选的左右 90°/180° 旋转起步。
- 非靶向旋转起步把 `CustomRotationType` 设为 `EAnimRot`；非旋转起步默认保持 `EHold`，仅当入状态时的速度卡迪纳尔方向为前向时切到 `EInterpolate`。这是角色旋转与动作阶段一致的关键。
- 起步可提前过渡到 Loop：非旋转起步第一步完成后，若旋转偏移达到 50° 或速度方向已改变，会请求切出；步态改变、距离匹配所需播放速率超出钳制范围、或动画接近结尾也会触发。
- 蹲伏走相同的靶向/非靶向选择规则，但不按 Walk / Run / Sprint 分组，使用 `CrouchAnimSet.Starts`。

## 常见问题

- **只导入四向起步，却开启 `HasRotatingStarts`。** 非靶向且输入角超过 60° 时会请求旋转起步资源；数据资产必须完整配置或关闭该开关。
- **把 `GetTimeAtDistance(1)` 的 `1` 当成「第一步」。** 距离曲线以 cm 为单位，`1` 是 1 cm ≈ 动画开头几帧；第一步的锚点是 `FirstStepAlpha`（按时间标记）。
- **把 Rotation Matching 当成替代距离匹配，或当成转身的节拍器。** 起步每帧仍按位移推进动作，旋转匹配只负责把旋转曲线值换算成朝向，转身节奏由距离匹配决定。
- **忽略从起步到 Loop 的提前切出。** 该切出防止起步方向已失效时仍强行播完，状态图的过渡条件需保留对应标记。
