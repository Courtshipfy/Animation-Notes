# Kai Locomotion：地面移动的输入与朝向模式

> Kai 不直接以“按了哪个方向键”选动画，而是将输入、速度和角色朝向换算为稳定的局部方向与地面状态。

## 解决的问题

同一份世界空间速度在角色朝向不同或处于靶向模式时，动画含义并不相同。若只用世界空间速度选动作，横移、后退、转身过程和 Warp 的输入都会混乱。Kai 先把移动状态规整为 `FKLSCharacterData`，让状态图与动画选择共享同一组语义数据。

## 工作方式

`UKLSLocomotionBlueprintLibrary::UpdateCharacterData()` 每次更新时，从移动组件和控制器收集位移、速度、加速度、Actor/控制器旋转，以及已有的 Pivot、瞄准和 Layer 信息。

| 原始量 | 规整后的动画输入 | 用途 |
| --- | --- | --- |
| 平面速度 | `LocalVelocity2D`、`LocalVelocityDirection`、`VelocityCardinalDirection` | 循环和停止方向 |
| 当前加速度 | `LocalAcceleration2D`、`LocalAccelerationDirection`、`InputCardinalDirection` | 起步与 Pivot 目标方向 |
| 控制器/Actor 朝向 | `AimOffsetRotation`、`DesiredRotation`、`RotationOffset` | 靶向、Turn in Place 与旋转匹配 |
| 最大速度 × 模拟输入强度 | `EffectiveSpeedScaler`、`SpeedGait` | Walk / Run / Sprint 的选择 |

局部方向由 Actor 旋转反变换后计算，再用 `SelectCardinalDirectionFromAngle()` 归入前、后、左、右四个卡迪纳尔方向。速度方向会保留上帧结果参与选择，输入方向则直接依当前加速度更新；因此“角色正在向哪里滑行”和“玩家此刻想向哪里走”是两个不同输入。

### 靶向与非靶向

库函数通过移动组件的 `bUseControllerDesiredRotation` 或角色的 `bUseControllerRotationYaw` 判断靶向。靶向时 `DesiredRotation` 取控制器旋转；非靶向时调用 `ComputeOrientToMovementRotation()`。两种模式都生成局部速度和局部输入方向，但身体朝向与输入方向的关系不同。

这解释了为什么 04 会把起步分成靶向与非靶向：差异从角色数据生成阶段就已经存在，而不是只发生在选动画的最后一步。

## 实现要点

- `bIsMoving` 与 `bIsAccelerating` 都排除 `HasRootMotionSources()` 为真的情况；不要把这套基于 Character Movement 的地面判断直接套到 Root Motion 驱动的状态。
- `EffectiveSpeedScaler` 是模拟输入强度乘以最大速度，不等同于当前 `Speed2D`。移动层据此确定步态。
- `OrientationWarpingAngle` 由局部速度方向和当前卡迪纳尔方向推导并插值；它是姿势修正的输入，不是重新选择一份八向循环动画。
- 模式切换、蹲伏切换或 Linked Layer 切换时，库函数会清除当前 Pivot 资格，避免用旧模式的数据延续反向动作。

## 常见问题

- **用速度方向代替输入方向做起步选择。** 角色刚输入反向时，速度仍可能指向旧方向；Kai 的起步应看局部加速度方向。
- **把四向分类当成只能四向移动。** 连续角度仍保留在 `LocalVelocityDirection`、`LocalAccelerationDirection` 和 Warping 输入中；四向值主要用于资源选择。
- **把靶向理解成单纯的 Aim Offset。** 靶向首先改变移动组件的目标朝向计算，Aim Offset 只是角色数据中记录的控制器与 Actor 的相对旋转。
