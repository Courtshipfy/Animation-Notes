# Kai Locomotion：角色移动组件的旋转与网络同步

> `UKLSCharacterMovementComponent` 将会影响动画观感的朝向、速度、加速度与 Pivot 信息纳入角色移动预测和复制，避免远端角色只同步位移而丢失运动表现的上下文。

## 解决的问题

地面动画不仅需要角色当前位置和速度，还依赖是否靶向、控制器朝向、当前自定义旋转、目标速度、加速度方向和是否正在 Pivot。若这些值仅保存在本地动画蓝图中，服务器校正或其他客户端上的模拟代理可能得到不同的朝向和状态，从而出现起步、转身或停止的表现不一致。

Kai 的移动组件继承 `UCharacterMovementComponent`，保留 UE 的移动预测框架，同时把上述动画相关状态接入移动更新和网络移动数据。

## 工作方式

### 1. 靶向状态决定基础旋转模式

在 `UpdateCharacterStateBeforeMovement()` 中，strafe 标记，或“瞄准且 `AutoStrafeWhenAiming`”会共同决定 `WantsToStrafe`。状态改变时，`RotationModeChanged()` 切换引擎移动组件的旋转策略：

- 靶向：关闭 `bOrientRotationToMovement`，启用 `bUseControllerDesiredRotation`；角色朝向服从控制器目标朝向。
- 非靶向：启用 `bOrientRotationToMovement`，关闭 `bUseControllerDesiredRotation`；角色朝向服从移动方向。

这正是后续“靶向与非靶向起步”要分篇讨论的基础：两种模式都能向同一个移动层提供状态，但身体朝向与输入方向的关系不同。

### 2. 特定动画可临时接管角色旋转

基础动画实例通过曲线 `KLSCustomRotation` 提供旋转权重。权重超过实例设定阈值（或接近 1），且没有 Root Motion Source 时，组件启用 `CFLAG_UseAnimCustomRot` 并取动画实例计算出的 `CustomRotationYaw`。

`PhysicsRotation()` 在该标记有效时用 `CustomRotationYaw` 作为目标 Yaw，并通过 `GetDeltaRotation()` 限制单帧转动；否则退回 `UCharacterMovementComponent` 的默认旋转实现。换言之，动画不能直接随意改 Actor 旋转，而是向移动组件提交一个由物理旋转阶段执行的目标朝向。

### 3. Pivot 是移动状态，也是动画选择的输入

`PhysWalking()` 比较加速度方向和速度方向的点积。当输入与当前速度近似反向、速度仍高于目标最大速度的一半且存在加速度时，组件设定 `bIsPivoting`；条件解除后清除。`GetMaxAcceleration()` 还会依据同一方向关系将最大加速度缩放到 `PivotMultiplier`。

因此 Pivot 同时影响运动学响应和动画状态，不应仅在动画蓝图中用“方向变化”自行猜测。

### 4. 自定义移动状态随预测移动传递

客户端保存移动时，`FKLSSavedMove` 记录 `CustomRotationYaw`、`MaxGroundSpeed` 和 `CustomMovementFlags`；这些值不同的移动不能合并。`FKLSNetworkMoveData` 将三项序列化进网络移动数据，`MoveAutonomous()` 在执行父类移动前恢复它们。

此外，组件向模拟代理复制加速度、strafe/aim、Pivot、最大地面速度、旋转方向、控制器旋转和 `StrafeRotAlpha`。这套设计的重点是让远端表现也能获得足够的动画判定上下文，并非复制整张动画状态机。

## 关键概念

- **Strafing（靶向）**：角色身体朝向以控制器目标朝向为主，移动方向可以与身体朝向分离。
- **非靶向移动**：启用 `bOrientRotationToMovement`，角色随移动方向转向。
- **Custom Rotation**：由动画曲线和动画实例数据授权、再由 `PhysicsRotation()` 落地的目标 Yaw。
- **Pivot**：输入加速度与现有速度方向相反时的运动过程；Kai 用它同时驱动加速度调整和动画状态。
- **Saved Move / Network Move Data**：UE 角色移动预测的扩展点；Kai 用其携带动画表现不可缺失的移动附加数据。

## 实现要点

- 接入 Kai 时需要让角色实际使用 `UKLSCharacterMovementComponent`；否则本文讨论的靶向、Pivot、自定义旋转和网络数据扩展不会执行。
- `MaxGroundSpeed` 在 `UseKLSReplicatedSpeed` 为真时覆盖走路、导航走路、下落和蹲伏时的最大速度选择；速度变化应经 `SetMaxGroundSpeed()` 或与复制策略一致的路径设置。
- `CFLAG_Strafing`、`CFLAG_UseAnimCustomRot`、`CFLAG_Aiming` 是移动预测中保存的自定义标记。新增会改变动画选择或旋转的状态时，应同时评估 Saved Move、序列化与模拟代理复制是否需要扩展。
- 本篇只说明“为何需要同步这些值”。起步动画怎样依据 `IsStrafing`、方向、蹲伏和步态进行选择，留给 04 专题。

## 常见问题

- **只在 AnimBP 中切换靶向变量。** 若不同时改变移动组件的旋转模式，角色物理朝向仍可能随移动方向变化，导致动画与胶囊体朝向不一致。
- **用本地速度推断远端 Pivot。** Kai 已复制 `bIsPivoting` 与动画相关的加速度信息；远端表现应优先使用已同步的状态，而不是另写一套不完全相同的阈值判断。
- **自定义旋转与 Root Motion 同时生效。** 当前实现仅在 `HasRootMotionSources()` 为假时启用动画自定义旋转；需要改变这项约束时，应先验证目标 Root Motion 工作流的所有权和网络行为。
