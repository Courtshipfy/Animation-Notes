# Kai Locomotion：动画数据、曲线与制作约定

> Kai 的距离匹配/旋转匹配不是运行时采样根运动，而是保存数据资产时预先从根运动把“时间 → 距离/旋转”缓存成曲线，运行时按剩余距离/角度反查时间。理解这套曲线缓存和命名约定，是接入和替换动作集的前提。

## 解决的问题

停止、Pivot、Turn in Place 都要回答同一个问题：**“还差多少距离/旋转，应该播到动画的哪一帧？”** 如果每帧都实时提取根运动再反查，开销大且不稳；如果只按固定播放速率播放，又无法和真实减速距离对齐。

Kai 的做法是“离线缓存、在线反查”：在编辑器保存数据资产时，把每段动画的根运动采样成两条曲线（`DistanceCurve`、`RotationCurve`），运行时用二分查找 + 线性插值，把“剩余距离/剩余旋转”映射回动画时间。本篇记录这套曲线的生成方式、查询函数和制作侧约定。

## 距离曲线与旋转曲线

`FKLSAnimData` 是动作集里每段动画的运行时封装，持有：

- `Animation`：`UAnimSequenceBase`（或 `UAnimComposite`）。
- `DistanceCurve` / `RotationCurve`：编辑器生成的 `FRichCurve`。
- `AverageSpeed`：根运动平均速度。
- `bIsStopAnim` / `bIsRotatingAnim` / `RotateDirection`：曲线语义标记。

### 生成（编辑器期，`#if WITH_EDITOR`）

`CacheDistanceCurve` / `CacheRotationCurve` 的采样率硬编码为 **60 Hz**（`CacheCurves` 传 `60.0f`）：

- **距离曲线**：对动画序列（或 Composite）逐采样时间提取根运动位置，把当前位置投影到“起点 → 终点”线段上（`ClosestPointOnSegment`），取到起点的 2D 距离作为曲线值。结果是“时间 → 累计前进距离”的单调曲线。
- **停止动画的距离曲线**：如果 `bIsStopAnim`，把曲线值改成 `累计距离 - 总距离`（再 clamp ≤ 0），变成“时间 → 距停止点剩余距离”的负值递减曲线，供停止距离匹配反查。
- **旋转曲线**：逐采样提取根运动 yaw，取 `|当前 yaw| / |最大 yaw|` 归一化到 0–1，得到“时间 → 旋转进度”。若总旋转 < 1° 则不生成。
- **平均速度**（`ExtractAverageSpeed`）：根运动 2D 距离 ÷ 播放长度，用于循环步态匹配。

生成过程会强制把源序列的 `bEnableRootMotion`、`bForceRootLock` 置为 true（并 `Modify()`），确保根运动可用。

### 反查（运行时）

`GetTimeAtDistance(Distance)` / `GetTimeAtRotation(Rotation)`：取曲线的 key 数组，用二分查找定位“最近的两个 key”，再按两 key 值线性插值出对应时间。`GetTimeAtDistance` 不 clamp 输入（调用方保证在范围内），`GetTimeAtRotation` 会把输入 clamp 到 `[Min, Max]`。

配套还有 `GetDistCurveValue(Time)` / `GetRotationCurveValue(Time)`（时间→值）和 `GetDistanceCurveMinMaxValues` / `GetRotationCurveMinMaxValues`（取范围）。

## 保存时自动缓存

数据资产的 `PreSave` 是曲线生成的入口（`KLSDataAssets.cpp`）：

- `UKLSLocomotionData::PreSave` → `StandingAnimations.CacheGaitCurves()` + `CrouchAnimSet.CacheCrouchCurves()`。
- 这两者递归调用 `CacheLoopsSpeed`、`CacheStartCurves`、`CacheStopCurves`、`CachePivotCurves`、`CacheTurnInPlaceCurves` 等，把整套动作集的距离/旋转曲线和平均速度都算好。
- `UKLSMaskingData::PreSave` → 对 Idle/Aim/Walk/Run/Sprint/CrouchIdle/CrouchAim/CrouchMoving/Jumping/Falling 各 Mask 调 `CacheAdditiveCurves()`。

含义是：**曲线是数据资产的一部分，保存即重建**。换动作集时，只要在编辑器里保存一次 Locomotion/Masking 数据资产，曲线就会按新动画重新生成，运行逻辑无需改动。

## 曲线命名约定

Kai 依赖一组按名字约定的动画曲线，角色数据更新和节点从中取值。

**基础曲线**（`FKLSAnimCurveNames`）：

| 曲线 | 含义 |
| --- | --- |
| `KLSSpeed` | 脚/根速度（Foot Placement 脚速默认来源之一） |
| `KLSGaitAlpha` | 步态混合 alpha |
| `KLSGrounded` | 接地状态 |
| `KLSLeftFootUp` | 左脚是否抬起（左右脚选择、起跳选择） |
| `KLSJumpWeight` | 跳跃权重 |
| `KLSPivotAlpha` | Pivot 进度 alpha |
| `KLSTurnInPlace` | 原地转身权重 |

**Mask 曲线**（`FKLSMaskCurveNames`）：按身体部位（`LegsMask`、`PelvisMask`、`SpineMask`、`HeadMask`、`RightArmMask`、`RightHandMask`、`LeftArmMask`、`LeftHandMask`），每部位带三个后缀：`_Add`（附加）、`_LS`（Local Space）、`_MS`（Mesh Space）。Mask 节点的 `WeightCurves` 就是引用这些名字（见 [15](./15_Mask节点_RandomPlayer与Slot.md)）。

换用不同骨骼或动作集时，这些曲线名必须保持一致，否则节点读不到权重、脚速或左右脚信息。

## 制作侧：Animation Modifiers 与压缩

插件随附一批 Animation Modifier（`Content/Animation_Modifiers/`，示例工程 `Animations/AnimModifiers/` 下另有若干）：

- `AM_AddCurves_BP`、`AM_AddTracks`：批量加曲线/轨道。
- `AM_RootMotionFromCurves`：从曲线生成根运动（与“从根运动抽曲线”相反的方向，用于曲线驱动的制作流程）。
- `AM_AutomaticSyncMarkers`、`ST_Foot_Sync_Definition`：自动同步标记与脚步同步定义。
- `TurnYawAnimModifier`、`FootFXAnimModifier`：转身 yaw、脚步特效相关。

这些资产说明 Kai 期望的制作流程是“在动画上批量打曲线/同步标记”，而不是手动画图。具体每个 Modifier 的行为需打开对应蓝图核对，本篇只记录其存在与命名。

插件依赖里的 `ACLPlugin`（Animation Compression Library）用于动画压缩，属于制作/打包侧的性能选项，不直接影响运行时动画逻辑。

## 实现要点

- 距离/旋转匹配的核心是 `GetTimeAtDistance` / `GetTimeAtRotation`：二分查找 + 两 key 线性插值。曲线采样率 60 Hz 决定了匹配精度上限。
- 停止动画的距离曲线是“负值递减”（距停止点剩余距离），与普通前进动画的“正值递增”语义相反；`bIsStopAnim` 决定生成哪种。
- 所有曲线在 `PreSave` 时重建，因此“保存数据资产”是动作集制作后的必要一步。
- 曲线名是硬约定：基础曲线、Mask 曲线、脚速曲线（`SpeedCurveName`）都要按约定命名，运行时按名字取值而非按引用。
- `FKLSLoopAnim` 只缓存 `AverageSpeed`（循环动画没有终点，不缓存距离/旋转曲线），与 05 篇的“循环匹配平均速度”一致。

## 常见问题与误解

- **以为匹配是运行时采样根运动。** 实际是编辑器预缓存曲线 + 运行时二分反查。
- **改了动画忘记重新保存数据资产。** 曲线不会自动更新；不重新保存，匹配用的还是旧曲线。
- **忽略曲线命名约定。** 换骨骼/动画后改了曲线名，脚速、左右脚、Mask 权重等按名字读取的地方会静默失效。
- **把循环动画也塞进距离曲线。** 循环无终点，只缓存平均速度；距离/旋转曲线用于有明确起点终点的起步/停止/Pivot/TIP。
- **把 `ACL` 当成运行时功能。** 它只影响动画压缩，属于制作/打包侧选项。
