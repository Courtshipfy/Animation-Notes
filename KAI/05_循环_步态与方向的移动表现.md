# Kai Locomotion：循环——步态与方向的移动表现

> 循环状态用“当前有效速度 → 步态 + 当前速度方向 → 四向循环”的两级选择，连续方向偏差交给 Orientation Warping 消化。

## 解决的问题

循环阶段要持续反映玩家的速度和方向变化，但不宜为每个角度切换一份序列。Kai 将动作资源控制在 Walk、Run、Sprint 各四向的循环集合，同时保留连续方向值供姿势修正使用。

## 工作方式

Linked Layer 更新时，`UpdateLinkedLayersValues()` 使用 `EffectiveSpeedScaler` 通过 `MotionSet->GetSpeedGaitFromSpeed()` 得到 Walk、Run 或 Sprint；并把当前步态对应的插值速度写回 Base Anim Instance。

站立循环选择由三个函数分别完成：

- `SelectStandingWalkAnimation()`
- `SelectStandingRunAnimation()`
- `SelectStandingSprintAnimation()`

每个函数都以 `VelocityCardinalDirection` 在前、后、左、右槽位中返回一份 `FKLSLoopAnim`，同时读取站立循环的播放速率钳制范围。局部速度的连续角度不会丢失：03 中生成的 `OrientationWarpingAngle` 仍可供后续姿势节点修正。

`SetupLoopState()` 将地面状态设为 `ELoop`，并把自定义旋转模式改为 `EInterpolate`。当前 C++ 的 `UpdateLoopState()` 未实现额外逻辑，因此 Loop 内的具体 BlendSpace、播放速率计算和姿势节点连接需要在 `KLS_BaseLinkedAnimBP` 图表中继续核验，不能从这段 C++ 推断。

## 实现要点

- 站立循环资产需要按三种步态和四个卡迪纳尔方向配置；Sprint 同样具有后、左、右槽位，不能假设只有前冲。
- `GetPlayRateClamp(false)` 取站立循环的播放速率范围；它用于限制距离匹配等状态的播放速度，不能用默认值代替数据资产配置。
- 步态切换的源数据是 `EffectiveSpeedScaler`，它受模拟输入强度影响。需要表现轻推摇杆时，应保留该输入，而不是只从当前速度阈值硬切。
- 本篇只讨论资源选择与状态职责；Orientation/Stride Warping 的骨骼求解留到运行时动画节点专题。

## 常见问题

- **把 `VelocityCardinalDirection` 用于起步。** 循环反映已经发生的运动，适合用速度方向；起步应使用输入/加速度方向。
- **用循环动画替代状态转换。** 起步、停止和 Pivot 都依赖距离/旋转曲线及显式时间，不能仅靠循环 BlendSpace 吸收。
- **把空的 `UpdateLoopState()` 误认为 Loop 没有更新。** 动画图、Sequence Player/BlendSpace 仍可能完成更新；这里只能确认 C++ 函数本身没有附加处理。
