# Kai Locomotion：循环——用速度维持步频，而非用距离追逐相位

> Loop 要连续回答三个问题：选哪个步态和方向锚点、以多快的步频重复、朝向残差怎么补。贯穿始终的前提是——Loop 用速度匹配而不是距离匹配：它没有要到达的终点，只让每个循环周期的平均位移速度等于角色实际速度。

## 解决的问题

持续移动中，角色速度会随摇杆力度、步态切换和移动组件加减速而变化。若动画步频不随之改变，每个循环周期都会累积脚滑；若反过来像起步、停止那样每帧按「距目标还差多少」重定位循环动画，又会打断本来连续的脚相。Loop 必须既跟上速度变化，又不破坏步相连续性。

## 全貌：一个前提，两个尺度，一处补正

理解 Loop 抓住一个前提、两个尺度和一处补正：

- **前提：速度匹配，不是距离匹配。** Loop 没有「应收束到的目标距离」，所以每帧不是「按距离曲线跳到某帧」，而是「调节播放速率」——只改变时间推进的斜率，不重设相位，脚相因此连续。
- **离散尺度：选资源。** 步态（Walk / Run / Sprint）+ 速度卡迪纳尔方向，选出一个四向姿势锚点。
- **连续尺度：调步频。** 在同一资源内，用 `SetPlayRateToMatchSpeed()` 按「实际速度 / 动画原始速度」调 `PlayRate`。
- **一处补正：填角度残差。** 四向锚点之间的角度，由 Orientation Warping 连续补足。

## 工作方式

### 选资源：步态 + 速度方向 → 四向锚点

步态来自 `EffectiveSpeedScaler` 的阈值归类（`GetSpeedGaitFromSpeed()`，与步态入口速度的中点比较，带滞回），而不是直接等于当前 `Speed2D`。方向取 `VelocityCardinalDirection`——**速度方向，不是输入方向**：Loop 描述的是角色正在怎样移动，不是下一瞬间想往哪里走。

选择结果是一份 `FKLSLoopAnim`，而不是四个资源的权重。因此方向层不是用 2D BlendSpace 在四条序列间持续插值，而是先选一个最适合承载步态的离散姿势锚点，再由 Orientation Warping 填满锚点之间的角度。

### 调步频：用播放速率匹配平均速度

`SetPlayRateToMatchSpeed()` 先从当前 `UAnimSequence` 的完整长度提取 Root Motion 平移，算出该资源在原始速率下的平均平面速度：

```text
AnimationSpeed = |RootMotion(0 → AnimLength)| / AnimLength
DesiredPlayRate = SpeedToMatch / AnimationSpeed
```

随后把 `DesiredPlayRate` 限制在动作集的 `PlayRateClamp` 内，写回 `Sequence Player`。角色实际速度是动画原始速度的 1.2 倍时，目标速率约 1.2；角色变慢，步频一起变慢。

它只改变后续时间推进的斜率，不会像 `Sequence Evaluator` 的距离匹配那样按曲线把时间跳到某个位置。这正是 Loop 能保持左右脚相位连续的原因：已落下的脚和下一次摆腿仍沿同一循环向前走，只是周期被拉长或压缩。

`PlayRateClamp` 是动画与移动参数之间的设计合同：

- 范围太窄，播放速率很快碰顶，剩余速度差表现为脚滑；
- 范围太宽，平均速度更接近，但步频、重心和落脚节奏被拉得不自然；
- 因此应先让序列的原始 Root Motion 平均速度接近该步态目标速度，再只用 Clamp 吸收小范围实时偏差。

函数要求序列有非零 Root Motion 平移，否则得不到 `AnimationSpeed`。即使胶囊体最终由 Character Movement 驱动，这段 Root Motion 仍是 Loop 的「每周期应走多远」标尺，不等同于必须由动画接管位移。

### 补朝向：Orientation Warping 填角度残差

每帧把速度转到角色局部空间得到 `LocalVelocityDirection`：一方面量化为 `VelocityCardinalDirection` 供资源选择，另一方面保留为连续值，计算当前运动方向相对被选资源的残差：

```text
前向资源：残差 = LocalVelocityDirection
右向资源：残差 = LocalVelocityDirection − 90°
左向资源：残差 = LocalVelocityDirection + 90°
后向资源：残差 = LocalVelocityDirection + 180°
```

Kai 把残差归一化后作为 `OrientationWarpingAngle` 的目标值，以插值速度 `10` 平滑逼近。于是 30° 前右移动不需要一条独立的 30° Loop：前向循环提供可信的步态、摆腿和重心，Orientation Warping 补足这 30° 的身体朝向。这正是四向资源能覆盖连续平面方向的原因。

### 扇区边界要有滞回，而不是硬切在 45°

`SelectCardinalDirectionFromAngle()` 的基础扇区是前向 `±45°`、后向 `±135°` 之外、其余为左/右；默认 Dead Zone `10°`，且当前方向为前或后时对应 Dead Zone 扩大一倍。因此从侧向进入前向需落入 `±55°`，已经是前向则保持到 `±65°` 才离开；后向也有相反方向的 10° 滞回。

滞回不改变运动方向，而是避免速度角在约 45° 或 135° 附近的微小抖动反复换 Loop 资源。Warping 负责扇区内的连续变化，滞回负责控制何时才值得换姿势锚点；两者共同避免「前向一帧、侧向一帧」的跳变。

四向资源本身也必须形成可切换的集合：至少对齐左右脚相位、循环起点、单周期时长、平均根位移速度和重心高度。Orientation Warping 只能修正方向残差，无法修复资源切换时左右脚相反、重心突变或步频不一致的问题。数据结构还预留了 `FwdLeanLeft` / `FwdLeanRight` 两条前向倾斜资源；当前已核实其存在与缓存，但尚未核实继承 Layer 图中如何混合，故本篇不写成确定的三向混合实现。

## 为什么 Loop 不做距离匹配

距离匹配回答的是「为了在一个指定事件处完成动作，现在动画应位于哪一帧？」它需要目标距离或累计位移，天然对应一段有起点和终点的非循环动作。

起步要让第一步落脚追上已发生的位移，停止要让减速动作在预测的停止位置收束，Pivot 要在转向结束时交还新的前进方向；这些都是一次性事件，所以 Kai 用 `Sequence Evaluator`、距离曲线或旋转曲线来定位和推进相位。

Loop 没有「到此为止」的目标距离。若每帧把它匹配到累计距离，循环边界会不断引入时间重定位，反而使脚相、通知和叠加动作失去连续性。它只需要让每一周期平均走过的距离与现实速度相称，因此用 `Sequence Player + PlayRate`。这也是两类动画工具在 Kai 中的分工边界，不是两种可互换的实现偏好。

## Loop 与瞬态动作的边界

Start、Stop、Pivot 的价值是消化不连续的运动事件；Loop 的价值是消化事件之后的持续运动。它接手时不再解释「第一步如何落下」「何时刹停」或「身体转过了多少度」，只维护已经建立的行进节奏。

因此状态切换应保持这个接口：

- Start / Post Pivot 只在移动方向和步态足以稳定表达时交给 Loop；
- Loop 发现输入与现有速度关系不再适合持续行走时，让 Stop 或 Pivot 接管，而不是在循环资源内部补起步、刹停或急转；
- 重新回到 Loop 后，先以新的速度方向选资源，再继续用速度比调该资源的周期。

这条边界让距离曲线、旋转曲线只服务于瞬态事件，循环资产专注于可重复的步态质量。对制作而言，循环序列应重点校准「每周期位移、步频、方向姿势及可接受的速率范围」；起停与转向序列则重点校准「事件发生时的相位和落脚」。

## 实现要点

- `Update Loop Anim` 绑定到 `Sequence Player`，每帧调用 `SetPlayRateToMatchSpeed`；播放器 Play Rate 必须是动态可写，否则函数输出警告且无法调速。
- 站立循环按 Walk、Run、Sprint 各自的前、后、左、右资源选择；`PlayRateClamp` 来自当前 `MotionSet` 的站立 Loop 配置，不要用全局默认范围覆盖动作集的校准结果。
- 用作 Loop 速度标尺的 Root Motion 总位移必须正确；循环中根位移为零或平均速度明显偏离步态预期时，播放速率公式失去意义，Clamp 只能掩盖不能修复问题。
- 速度匹配只能修正平均位移速度，不能替代方向变化的姿势修正或极端速度差的动作设计；这些问题分别留给 Orientation/Stride Warping 与资源、步态、瞬态状态的边界处理。

## 常见问题

- **把 Loop 当作距离匹配的长版。** 循环没有应收束到的目标距离；重定位时间会损害步相连续性，应调播放速率而非持续跳时间。
- **按输入方向切循环。** 输入反向瞬间角色往往仍沿旧速度滑行；Loop 应看速度方向，反向这一段由 Pivot 表达。
- **把四向资源当成四向 BlendSpace。** Kai 先离散选一个资源，再以 Orientation Warping 修正扇区内角度；四向序列脚相不一致，不能靠 Warping 或 Play Rate 修复。
- **只按速度调 Play Rate，却不校准原始序列。** 公式依赖序列的平均 Root Motion 速度；错误的根位移会把所有实时调速建立在错误基准上。
- **用很宽的 Clamp 解决所有速度范围。** 这会把节奏失配隐藏为夸张的快放/慢放；超出可接受范围时应检查步态阈值、移动速度或补充动作，而不是无限扩展 Clamp。
