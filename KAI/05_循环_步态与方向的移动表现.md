# Kai Locomotion：循环——用速度维持步频，而非用距离追逐相位

> Loop 的职责不是「播一段走路动画」，而是在没有终点的持续移动中，让动作的平均位移速度与角色实际速度保持一致；起步、停止和 Pivot 才处理有明确事件边界的相位对齐。

## 解决的问题

循环移动最容易被误解成一段可以按固定速率重复播放的动画。但角色速度会持续变化：推摇杆的力度、步态切换和移动组件的加减速都会改变实际地面速度。若动画步频不随之变化，角色会在每一个循环周期累积脚滑；若反过来每帧都按「距某个目标还差多少」重定位循环动画，又会破坏本来连续的步相。

Kai 把这两个问题拆开：用离散的资源选择决定「当前是哪一种行进步态和主方向」，用连续的播放速率决定「这一个循环要以多快的步频重复」。Loop 因而是一个稳定调速器，而不是距离匹配状态。

## 核心匹配模型：匹配平均速度，不重设循环相位

`SetPlayRateToMatchSpeed()` 会先从当前 `UAnimSequence` 的完整长度提取 Root Motion 平移，计算该资源在原始速率下的平均平面速度：

```text
AnimationSpeed = |RootMotion(0 → AnimLength)| / AnimLength
DesiredPlayRate = SpeedToMatch / AnimationSpeed
```

随后把 `DesiredPlayRate` 限制在动作集的 `PlayRateClamp` 内，并写回 `Sequence Player`。也就是说，角色实际速度为动画原始速度的 1.2 倍时，播放器目标速率也是约 1.2；角色变慢时，步频一起变慢。

它只改变后续时间推进的斜率，不会像 `Sequence Evaluator` 的距离匹配那样按曲线把时间跳到某个位置。这个区别正是 Loop 能保持左右脚相位连续的原因：已经落下的脚和下一次摆腿仍按同一循环向前走，只是周期被拉长或压缩。

`PlayRateClamp` 不是随意的保护值，而是动画与移动参数之间的设计合同：

- 范围太窄，播放速率很快碰顶，剩余的速度差会表现为脚滑；
- 范围太宽，虽然平均速度更接近，但步频、重心和落脚节奏会被拉得不自然；
- 因此应先让序列的原始 Root Motion 平均速度接近该步态目标速度，再只用 Clamp 吸收小范围的实时偏差。

函数要求序列具有非零的 Root Motion 平移；否则无法得到 `AnimationSpeed`，也就不会用播放速率匹配。即使项目最终是由 Character Movement 驱动胶囊体，这段 Root Motion 仍是 Loop 的「每周期应走多远」标尺，而不等同于必须由动画接管位移。

## 两个时间尺度：离散换资源，连续调步频

Loop 的资源选择和播放更新解决的是不同频率的问题，不能混为同一套 Blend 逻辑。

| 时间尺度 | 输入 | 输出 | 设计含义 |
| --- | --- | --- | --- |
| 离散变化 | `EffectiveSpeedScaler` 归类出的 Walk / Run / Sprint，加上 `VelocityCardinalDirection` 的前后左右 | 一份 `FKLSLoopAnim` | 当实际运动已经形成后，选与当前步态及**速度方向**相符的循环动作。 |
| 连续变化 | `SpeedToMatch` | `Sequence Player.PlayRate` | 在同一动作内跟随速度的细小波动，维持步频与地面速度的比例。 |

方向这里取速度而非输入或加速度：Loop 描述的是角色**正在怎样移动**，不是下一瞬间想往哪里移动。玩家刚反向输入时，旧的速度方向仍然存在；此时若立即把 Loop 当作新方向资源，会把正在发生的制动/转向误表示成横移或倒走。Kai 将这种输入与速度尚未一致的瞬态交给 Pivot，直到运动重新稳定后，Loop 才以新的速度方向成为表象。

同理，`SpeedGait` 的选择来自 `EffectiveSpeedScaler` 的阈值归类，而不是每个速度值都寻找一条新动画。资源切换是有限集合上的决策；速度匹配在被选中的序列内连续工作。将两者分开，才能既控制资源规模，又不把手柄微小输入直接放大为频繁的动画切换。

## 为什么 Loop 不做距离匹配

距离匹配回答的是「为了在一个指定事件处完成动作，现在动画应当位于哪一帧？」它需要目标距离或累计位移，也天然对应一段有起点和终点的非循环动作。

起步要让第一步落脚追上已经发生的位移，停止要让减速动作在预测的停止位置收束，Pivot 要在转向过程结束时交还新的前进方向；这些都是一次性的事件，所以 Kai 用 `Sequence Evaluator`、距离曲线或旋转曲线来定位和推进相位。

Loop 没有「到此为止」的目标距离。若每帧把它匹配到累计距离，循环边界会不断引入时间重定位，反而使脚相、通知和叠加动作失去连续性。它只需要让每一周期平均走过的距离与现实速度相称，因此使用 `Sequence Player + PlayRate`。这也是两类动画工具在 Kai 中的分工边界，而不是两种可以互换的实现偏好。

## Loop 是瞬态动作交付稳定运动的接口

Start、Stop、Pivot 的价值是消化不连续的运动事件；Loop 的价值是消化事件之后的持续运动。它接手时不再试图解释「第一步如何落下」「何时刹停」或「身体转过了多少度」，只维护已经建立的行进节奏。

因此，设计状态切换时应保持这个接口：

- Start / Post Pivot 只在移动方向和步态足以稳定表达时交给 Loop；
- Loop 发现输入与现有速度关系不再适合持续行走时，应让 Stop 或 Pivot 接管，而不是试图在循环资源内部补一段起步、刹停或急转；
- 重新回到 Loop 后，先以新的速度方向选资源，再继续用速度比调节该资源的周期。

这条边界让距离曲线、旋转曲线只服务于瞬态事件，而让循环资产专注于可重复的步态质量。对制作而言，循环序列应重点校准「每周期位移、步频、方向姿势及可接受的速率范围」；起停与转向序列则重点校准「事件发生时的相位和落脚」。

## 实现要点

- `Update Loop Anim` 绑定到 `Sequence Player`，每帧调用 `SetPlayRateToMatchSpeed`；播放器的 Play Rate 必须是动态可写，否则函数会输出警告且无法调速。
- 站立循环按 Walk、Run、Sprint 各自的前、后、左、右资源选择；`PlayRateClamp` 来自当前 `MotionSet` 的站立 Loop 配置。不要用全局默认范围覆盖动作集的校准结果。
- 用作 Loop 速度标尺的 Root Motion 总位移必须正确。循环中根位移为零，或平均速度明显偏离该步态的预期速度时，播放速率公式失去意义，Clamp 只能掩盖而不能修复问题。
- 速度匹配只能修正平均位移速度，不能替代方向变化的姿势修正或极端速度差的动作设计；这些问题分别留给方向/Stride Warping 与资源、步态、瞬态状态的边界处理。

## 常见问题

- **把 Loop 当作距离匹配的长版。** 循环没有一个应收束到的目标距离；重定位时间会损害步相连续性，应调播放速率而非持续跳时间。
- **按输入方向切循环。** 输入反向的瞬间，角色往往仍沿旧速度滑行；Loop 应看速度方向，反向这一段由 Pivot 表达。
- **只按速度调 Play Rate，却不校准原始序列。** 公式依赖序列的平均 Root Motion 速度；错误的根位移会把所有实时调速建立在错误基准上。
- **用很宽的 Clamp 解决所有速度范围。** 这会把动作本身的节奏失配隐藏为夸张的快放/慢放。超出可接受范围时，应检查步态阈值、移动速度或补充对应动作，而不是无限扩展 Clamp。
