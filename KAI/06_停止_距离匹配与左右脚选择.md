# Kai Locomotion：停止——距离匹配与左右脚选择

> 停止动画不从 0 秒硬播；Kai 先预测还会滑行多远，再从距离曲线上找与该剩余距离对应的动画时间，并在资源允许时依据抬起的脚选择版本。

## 解决的问题

角色松开输入后，速度并不会立刻归零。如果停止动画总从同一帧开始，角色脚步与真实减速距离容易错位；如果忽略当前支撑脚，停止时还可能出现重脚或脚底滑动。

## 工作方式

进入站立 Stop 时，系统读取 `LeftFootUpCurve` 得到 `IsLeftFootUp`，再以**速度卡迪纳尔方向**、当前步态、左右脚和是否蹲伏选择停止动画。`PredictGroundMovementStopLocation()` 预测停止位移，`GetTimeAtDistance(-StopDistance)` 将 `Sequence Evaluator` 直接定位到相应时间。

随后每帧仅在“仍在移动且不再加速”时调用 `DistanceMatchToTarget()`，把预测停止距离、当前动画的距离曲线和数据资产的 Stop Distance Threshold 一起传入。动画接近结尾 0.2 秒时设置 `StandingStopBlendToLoop`，让状态图进入后续状态。

资源选择有两层：先按 Walk / Run / Sprint 选停止集，再按当前速度方向选前后左右；如果该集启用 `UsePerFootStop` 且左脚抬起，则取 `LeftFootUp`，否则取 `RightFootUp`。蹲伏版本使用相同逻辑，但只从 `CrouchAnimSet.Stops` 读取资源和阈值。

## 实现要点

- 停止动画的距离曲线是距离匹配的前提；无曲线或曲线与实际 Root 位移不一致时，显式时间定位会失真。
- `LeftFootUpCurve` 的语义需要与动作资源的 Left/Right Foot Up 配置一致。它是选动画的输入，不是纯调试曲线。
- 停止状态一旦重新出现加速度就不再继续更新距离匹配，避免将减速动作错误推进到新起步过程。
- 停止的终点由 Movement Component 的预测决定；修改制动、摩擦或最大速度后，应重新观察停止距离与曲线是否仍匹配。

## 常见问题

- **用输入方向选停止动作。** 松开输入时没有可靠的当前输入方向，Kai 依据的是残余速度方向。
- **只配置一个脚相版本却保留 `UsePerFootStop`。** 选择器会按曲线请求两套数据；缺失资源会造成选择错误或空资产。
- **把停止距离阈值当作动画长度。** 它传给距离匹配逻辑以判断如何接近目标，不是 Sequence 的播放时长。
